## 1. 目的と範囲

### 1.1 何を作るか

**紙のカードと盤面をブラウザ上に置き換えた、ルール判定のない対戦用の卓。** カードを出す・動かす・数値を書き換える・山札を引くといった操作は人が手で行い、ルールが正しいかは人が判断する。紙で遊ぶのと同じ感覚で、印刷や数字のメモの手間なしに試遊できることを目指す。

### 1.2 目的

| 目的 | 内容 |
|---|---|
| ルールとカードの面白さを早く確かめる | ルールエンジン（M1）を作る前に、同時戦闘・レーン・予備マナ・遅延・リーダーの成長が面白く回るかを試す |
| 数値感をつかむ | 1試合の長さ（ラウンド数・時間）、リーダーが成長するラウンド、強すぎる・弱すぎるカードを見つける |
| 紙より速く回す | シャッフル・ドロー・マナの増減・ダメージの記録などの手間を減らし、1試合を短く回せるようにする |
| 記録を残す | 操作の記録（ログ）と試合の結果を残し、調整の材料にする |

### 1.3 作らないもの

| 作らないもの | 理由 |
|---|---|
| ルールの判定（合法かどうかのチェック、戦闘の自動計算、効果の自動処理） | ルールエンジン（M1）の担当。モックアップは人が判断する |
| AI | M2 以降 |
| 見た目の演出・アニメーション | 試遊の効率に関係しない |
| オンライン対戦 | 1台の画面で遊ぶ |

ルール判定はしないが、**紙で遊ぶときに面倒な「記録と計算」だけは手伝う**（5章の補助機能）。補助機能はすべて任意で、使わずに手で操作することもできる。

## 2. 遊び方の想定

| 遊び方 | 内容 |
|---|---|
| 1人で両方を動かす（一人回し） | 主な使い方。2つのデッキを1人で交互に動かし、ルールとカードを確かめる |
| 2人で1つの画面を使う | 交代で操作する。相手の手札を隠す表示に切り替えられる |

画面には常に「今どちらのプレイヤーの視点か」を表示し、ボタン1つで入れ替えられる（6.5）。

## 3. 画面構成

```
┌──────────────────────────────────────────────────────────────┐
│ ラウンド 5 ／ 行動フェイズ ／ 先手: B ／ 行動権: A   [補助▼][ログ][保存] │  ← 上部バー
├──────────┬─────────────────────────────────────────┬─────────┤
│ Bの情報   │  B 手札（裏向き or 表向き）                  │ Bの山札 │
│ ライフ 17 │                                          │ 28枚    │
│ マナ 3/5  ├─────────────────────────────────────────┤ トラッシュ│
│ 予備 4    │   B 後列 [   ][   ][   ][   ]             │ 除外    │
│ リーダー  │   B 前列 [   ][   ][   ][   ]             │         │
│ 遅延ゾーン │  ════════════ 戦線 ════════════            │         │
├──────────┤   A 前列 [   ][   ][   ][   ]             ├─────────┤
│ Aの情報   │   A 後列 [   ][   ][   ][   ]             │ Aの山札 │
│ …        ├─────────────────────────────────────────┤ トラッシュ│
│          │  A 手札                                   │ 除外    │
├──────────┴─────────────────────────────────────────┴─────────┤
│ 選択中のカードの詳細（名前・コスト・能力値・キーワード・効果文）        │  ← 下部パネル
└──────────────────────────────────────────────────────────────┘
```

- 盤面は 4レーン × 前列・後列 × 2人。レーン番号（1〜4）を表示する。
- 画面の下側が「今の視点のプレイヤー」になる。視点を入れ替えると上下が入れ替わる。
- 横長のPC画面を前提とする（スマホ対応はしない）。

## 4. 表示する要素

### 4.1 プレイヤーごと

| 要素 | 表示 | 手で変更 |
|---|---|---|
| ライフ | 数値 | ＋／－ボタン、直接入力 |
| 最大マナ・通常マナ | 「通常 3 / 最大 5」 | ＋／－ |
| 予備マナ | 数値（上限＝最大マナを超えたら警告色） | ＋／－ |
| 使い残した通常マナ（次ラウンドの予備マナ加算分） | 終了フェイズで記録した値 | ＋／－ |
| 使ったスペルの枚数 | 数値（魔法の剣・大賢者の幻影用） | ＋／－ |
| リーダー2人 | 名前・段階（通常／成長）・能力とコスト・パッシブ・成長条件の進み具合・今ラウンドに使ったか | 進み具合の＋／－、成長の切り替え、使用済みの切り替え、能力コストの増減（ノエル） |
| 山札 | 枚数（中身は見えない） | 引く・シャッフル・上から見る（4.3） |
| 手札 | カードの一覧。視点のプレイヤー以外は裏向きにできる | ドラッグで盤面・トラッシュなどへ |
| トラッシュ・除外ゾーン | 枚数。クリックで一覧 | 一覧から手札・山札などへ戻す |
| 遅延ゾーン | 予約中の遅延効果（カード名・対象のメモ・予約した順） | 追加・発動済みにする |

### 4.2 盤面のユニット

マス1つに1体。カードには次を表示する。

| 表示 | 内容 |
|---|---|
| 名前・コスト | |
| 攻撃力 / 残り体力 | 元の値から変わっていれば色を変える（強化は緑、弱体化・ダメージは赤） |
| 受けているダメージ | 例: 「体力 6（ダメージ 2）」 |
| キーワード | 生まれつきのものと、付与されたものを区別して表示（付与は「このラウンド中」かどうかも） |
| マーカー | 盾・「このラウンド中の強化」・「起動済み」「機動済み」など（4.4） |
| トークン | 効果で出したユニットは「トークン」と表示（破壊されたらトラッシュに行かず消える） |

### 4.3 山札の操作

| 操作 | 内容 |
|---|---|
| 1枚引く | 手札が10枚なら警告を出し、トラッシュに置くか選べる |
| シャッフル | |
| 上から N 枚を見る | 見た中から1枚を手札へ、残りを元の順番で上に戻す（データ検索用） |
| 条件に合うカードをランダムに手札へ | 「ユニット」「スペル」を指定（兵士招集・図書委員用）。その後自動でシャッフル |
| 山札から探す | 一覧から選んで手札へ（テストや巻き戻し用） |

### 4.4 マーカー

ユニットに付けたり外したりできる目印。ルール上の効果は人が判断する。

| マーカー | 用途 |
|---|---|
| 盾 | 盾を持っている。ダメージを1回防いだら外す |
| このラウンド中 +X/+Y | 一時的な強化・弱体化。ラウンド終了の補助で自動的に外れる |
| このラウンド中のキーワード | 例: このラウンド中 先制 |
| 起動済み・機動済み | 1ラウンド1回の制限の記録。ラウンド開始の補助で外れる |
| ラウンド終了時に処理 | オーバークロック（2ダメージ）・崩落の予言（破壊）の予定。ラウンド終了の補助で「処理してください」と知らせる |
| 自由なメモ | 短い文字を付けられる |

マスそのものにも「遅延の予告」（例: 崩落の予言・軌道レーザー照準の対象）の印を付けられる。

## 5. 補助機能（任意）

ルールは判定しないが、**毎ラウンド同じ手順になる記録と計算** はボタン1つで行えるようにする。どれも実行前に内容を表示し、実行後に取り消せる。

| 補助 | 内容（ルール仕様書の手順） |
|---|---|
| ラウンド開始 | ラウンド数+1 → 最大マナ+1（上限10）→ 使い残した通常マナを予備マナに加算（上限＝最大マナ）→ 通常マナ全回復 → 双方1枚ドロー → 先手トークンを移す → 起動済み・機動済み・リーダー使用済みのマーカーを外す（6.1） |
| ラウンド終了 | 「ラウンド終了時に処理」の一覧を表示 → 「このラウンド中」のマーカーを外す（一時的な体力が受け止めたダメージも消す: 10.4）→ 使い残した通常マナを記録（6.4） |
| 手番の交代 | 行動権を相手に移す。直前がパスかどうかを記録し、双方が続けてパスしたら「戦闘フェイズへ」と表示する。即効のときは「追加の手番」ボタンで交代しない |
| 遅延の予約と発動 | 予約を遅延ゾーンに記録し、予約したプレイヤーの次の手番の始めに「遅延効果を発動してください」と表示する |
| コストの支払い | 「3支払う（予備マナから優先）」のように入力すると、通常マナ・予備マナを減らす。内訳は変えられる |
| ダメージ・回復の入力 | ユニットを選んで数値を入力。盾マーカーがあれば「盾で防ぎますか？」と確認する。体力が0以下になったら「破壊しますか？」と確認する |
| 勝敗の確認 | ライフが0以下になったら知らせる（判定は人が行う） |

**戦闘の自動計算はしない**。戦闘は、盤面を見ながら人がダメージを入力して処理する。自動計算はルールエンジン（M1）で作る。

## 6. 操作

### 6.1 基本の操作

| 操作 | 方法 |
|---|---|
| カードを動かす | ドラッグ＆ドロップ（手札 → マス、マス → マス、マス → トラッシュ・手札・除外など） |
| カードの詳細を見る | カードにマウスを乗せる、またはクリック → 下部パネルに表示 |
| ユニットのメニュー | 右クリック: ダメージ・回復・攻撃力／体力の増減（永続／このラウンド中）・キーワードの付与・マーカー・破壊・手札に戻す・除外・前進 |
| 手札のカードのメニュー | 右クリック: コストの増減（重装ガンシップ・魔導ゴーレム用）・公開・トラッシュへ |
| 取り消し／やり直し | Ctrl+Z ／ Ctrl+Y（何回でも） |

### 6.2 カードを出す

| 操作 | 内容 |
|---|---|
| 手札から配置 | 手札のユニットを空きマスへドラッグ。コストを支払うか確認する（補助を使う場合） |
| スペルを使う | 手札のスペルを「使用」エリアへドラッグ。遅延を持つスペルなら遅延ゾーンへ、そうでなければトラッシュへ。「使ったスペルの枚数」を効果の後に+1 |
| 効果でユニットを出す | カード一覧からカードを選んで空きマスへ（偵察ドローン・学院の石像用）。トークンとして扱う |
| 手札に生成する | カード一覧からカードを選んで手札へ（魔力還元・偵察ドローン・禁書の閲覧用） |

### 6.3 リーダーの操作

- 能力の使用: リーダーをクリック → 「能力を使う」。コストの支払い（補助）と使用済みの記録を行う。
- 成長条件の進み具合: ＋／－。条件に達したら「成長しますか？」と確認する。
- パッシブは常に表示する（効果の適用は人が判断する）。

### 6.4 ログ

- すべての操作を時刻・ラウンド・プレイヤーとともに自動で記録する（例:「R5 A 城壁の守り手 を 2前 に配置（コスト5）」）。
- 手でメモを書き込める（例:「騎士の決闘の処理に迷った」）。
- ログはテキストで書き出せる。試遊後の振り返りと、ルール・カードの修正に使う。

### 6.5 視点と表示

| 設定 | 内容 |
|---|---|
| 視点の入れ替え | 下側に表示するプレイヤーを入れ替える。手番の交代に合わせて自動で入れ替えることもできる |
| 相手の手札 | 表向き／裏向きを切り替える（一人回しでは表向き、2人で遊ぶときは裏向き） |
| カードの効果文の表示 | 盤面のカードに効果文を小さく出すか、詳細パネルだけに出すか |

## 7. 試合の準備

1. **デッキを選ぶ**（プレイヤーごと）
   - 保存済みのデッキから選ぶ。
   - その場で作る: リーダー2人（異なる勢力）を選び、2勢力のカードから40枚（同名3枚まで）を選ぶ。条件を満たさないときは警告する（作ることはできる）。
   - おまかせ: リーダー2人を選ぶと、2勢力から40枚をランダムに組む（試しに遊ぶ用）。
2. **先手を決める**: ランダム、または手で選ぶ。
3. **初期手札**: 双方4枚引く。
4. **マリガン**: 戻すカードを選ぶ → 同じ枚数を引く → 戻したカードを山札に入れてシャッフル（3.3）。
5. 第1ラウンドを始める（「ラウンド開始」の補助）。

デッキは `data/decks/` の形式（card-data.md 9章の案: リーダー2人＋カードIDと枚数）で保存・読み込みする。

## 8. 保存と記録

| 機能 | 内容 |
|---|---|
| 自動保存 | 操作のたびにブラウザ（localStorage）に保存し、ページを閉じても続きから遊べる |
| 試合の書き出し・読み込み | 試合の状態を JSON ファイルとして保存・読み込み。途中の局面を保存して、同じ場面を何度も試せる |
| 試合結果の記録 | 試合の終わりに、勝者・ラウンド数・かかった時間・各リーダーが成長したラウンド・メモを記録する。一覧で見られ、CSV で書き出せる |

## 9. 技術構成

| 項目 | 方針 |
|---|---|
| 言語・ツール | TypeScript ＋ Vite（本番のブラウザ版と同じ）。UIフレームワークは使わず、DOM を直接操作する |
| 置き場所 | リポジトリの `mockup/` フォルダ。本番のコード（M1〜）とは分ける |
| カードデータ | `data/cards/*.json` をそのまま読み込む（ビルド時に取り込む）。表示に使うのは名前・コスト・能力値・キーワード・効果文（`text`）・リーダー情報だけで、`effects` などの構造化データは使わない |
| 状態の持ち方 | 試合の状態を1つの JSON にできるデータ（9.1）として持つ。取り消しは操作のたびの状態のコピーで行う |
| 乱数 | シャッフル・ランダムはシード付きの乱数を使い、試合の書き出しにシードを含める |
| 公開 | GitHub Pages などの静的ホスティング。サーバーは不要 |

### 9.1 状態のデータ（概要）

```ts
type MockState = {
  round: number;
  phase: "start" | "action" | "combat" | "end";
  firstPlayer: "A" | "B";
  activePlayer: "A" | "B";
  lastActionWasPass: boolean;
  players: Record<"A" | "B", PlayerState>;
  log: LogEntry[];
  seed: number;
};

type PlayerState = {
  life: number;
  maxMana: number; mana: number; reserve: number; unusedMana: number;
  spellsCast: number;
  leaders: LeaderState[];          // 2人
  deck: CardInstance[];            // 山札（上が先頭）
  hand: CardInstance[];
  trash: CardInstance[];
  exile: CardInstance[];
  delayed: DelayedEntry[];         // 遅延ゾーン
  board: (UnitOnBoard | null)[];   // 8マス（盤面の順番: 1前,1後,2前,2後,…）
};

type CardInstance = { uid: string; cardId: string; costModifier: number; revealed: boolean; generated: boolean };
type UnitOnBoard = CardInstance & {
  attackMod: number; healthMod: number; damage: number;
  tempAttack: number; tempHealth: number;        // このラウンド中
  keywordsAdded: string[]; tempKeywords: string[];
  markers: string[]; isToken: boolean;
};
type LeaderState = { leaderId: string; grown: boolean; progress: number; usedThisRound: boolean; abilityCostMod: number };
type DelayedEntry = { uid: string; cardId: string; note: string; reservedAt: number; readyToFire: boolean };
type LogEntry = { time: string; round: number; player: "A" | "B"; text: string };
```

- ルールエンジンの状態（M1）とは別物で、手で動かすための最小限の情報だけを持つ。

## 10. 作業の分け方

| # | タスク | 完了条件 |
|---|---|---|
| MK-1 | `mockup/` の開発環境を作り、カードデータを読み込んで一覧表示する | 3勢力75枚とリーダーが表示できる |
| MK-2 | 盤面・手札・山札・トラッシュ・除外・リーダーゾーンを表示する | 3章の画面構成が表示される |

MK-1〜6 までで「紙と同じように遊べる最小版」、MK-7 以降で「紙より速く回せる版」になる。

## 11. 確認事項

| # | 項目 | 案 |

| 5 | 置き場所と公開 | `mockup/` に置き、GitHub Pages で公開する |
