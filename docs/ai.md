> 対戦相手の AI の考え方を、実装できる細かさで書いたもの。強さは **やさしい（easy）・ふつう（normal）・つよい（hard）** の3段階。

## 1. 共通の前提

### 1.1 使ってよい情報

AI は人間と同じく、**自分から見える情報だけ** で判断する（ルール仕様書 4章）。

| 情報 | 使うか |
|---|---|
| 盤面・トラッシュ・除外・遅延ゾーン・リーダー・ライフ・マナ・予備マナ | 使う（公開情報） |
| 自分の手札 | 使う |
| 相手の手札のうち公開されたカード | 使う |
| 相手の手札（公開されていないもの）・相手の山札 | **使わない**。枚数だけ使う |
| 自分の山札 | 順番は使わない。つよいは「中身（自分のデッキ）」だけ使う（4.2） |

実装では、判断の前に状態を `publicView(state, 自分)` で公開情報だけにする。隠れたカードは仮のカード（**王都の弓兵 KN-03**。よくある安いユニットとして扱う）に置き換えてから、エンジンで先を試す（1.4）。

### 1.2 行動フェイズ以外の判断

| 場面 | 判断 |
|---|---|
| マリガン | やさしい: コスト5以上のカードをすべて戻す。ふつう・つよい: 相手の勢力ごとの「初手にあると勝ちやすいか」の表を使う（下記） |
| 山札の上から見て1枚選ぶ（データ検索など） | 一番コストの高いカードを選ぶ（3段階とも同じ） |

**ふつう・つよいのマリガン**（`engine/src/mulligan.ts`）

1. 手札の各カードの「見込み」を、表 `engine/src/mulligan-table.json` から引く。表の値は「そのカードが初手の4枚にあった試合の勝率が、同じ組み合わせ（自分のデッキ・相手のデッキ・先手か後手か）の平均より何ポイント高かったか」で、**相手の勢力ごと**に持つ。相手の勢力はリーダーで分かるので、相手の2つの勢力の値の平均を使う。
2. 表にないカードは、コストで決める（4コスト −1、5コスト以上 −4 から重いほど下げる）。
3. 代わりに引くカードの見込み = 自分の山札（自分のデッキの中身は知っている）の見込みの平均。これより悪いカードを戻す（余裕 0。0〜3ポイントを比べて一番よかった）。
4. 表は AI 同士の対戦（ふつう、双方マリガンなし）から作る: `cd engine && npm run mulligan-table`。見本デッキ同士の対戦に加えて、見本デッキに入っていないカードも表に載るように、勢力の組ごとに乱数で組んだ調査用のデッキも混ぜる。試合数の少ないカードの値は 0 に寄せる。カードやルールを変えたら作り直す。
5. 旧方式（コスト5以上を戻す）との比較（`npx tsx scripts/mulligan-ab.ts`。同じシードで方針を入れ替えた2試合ずつ。デッキは見本3つ＋表づくりに使っていない騎士団＋学院のデッキ）:

| 強さ | 余裕 | 新方式の勝率 | 戻した枚数（新 / 旧） |
|---|---|---|---|
| ふつう | 0（採用） | 53.0% ±1.9（2560試合） | 1.94 / 0.66 |
| ふつう | 1 | 52.3% ±1.9（2560試合） | 1.43 / 0.66 |
| ふつう | 2 | 51.7% ±1.9（2560試合） | 0.97 / 0.66 |
| ふつう | 3 | 51.5% ±1.9（2560試合） | 0.59 / 0.66 |
| つよい | 0 | 51.4% ±6.1（256試合） | 1.88 / 0.63 |

（この比較はカードリスト v0.7 のときのもの。表はカードリスト v0.8 で作り直した。）ふつうでは4デッキとも勝率が上がった（+1.5〜+10ポイント。表づくりに使っていないデッキは +1.5）。つよいは試合数が少なく、差は誤差の範囲。

### 1.3 候補の手

- 行動フェイズでは、合法手の一覧（`legalActions`）をすべて候補にする。カード × マス × 対象 × 強化するか、遊撃の移動先、起動能力、リーダー能力、パス。
- 強化・起動・リーダー能力のコストは、ルールどおり予備マナから先に払う（ルール仕様書 16.2）。支払いの内訳は候補に入らない。

### 1.4 1手の評価（1手読み）

候補の手 a ごとに、次の手順で「その手を打った後の評価値」を出す。

1. 公開情報の状態で a を実際に適用する（エンジンの `applyAction`）。
2. 結果に応じて評価する。
   - **試合が終わった**: 勝ちなら +1000、負けなら −1000、引き分けなら 0。
   - **効果の途中で選択が必要になった**（データ検索など）: 手を打つ前の評価に +0.5。
   - **ラウンドが終わって次のラウンドに進んだ**（相手がパスした後に自分もパスした場合など）: その状態をそのまま評価する（3章。「ラウンドの終わり」として扱う）。
   - **それ以外**: 「このまま戦闘になったら」を計算し（`previewCombat`）、その結果の状態を評価する。予約中の遅延効果は戦闘の前に必ず発動するので、先に発動させてから戦闘を計算する。

つまり、どの手も「**このラウンドの戦闘が終わった時点で、盤面がどうなっているか**」で比べる。相手がこの後に打つ手は考えない（つよいを除く）。

### 1.5 手の選び方

- 評価値が一番高い手を選ぶ。
- ただし、パス以外の手は **パスより 0.05 以上良いときだけ** 選ぶ。同じくらいならパスする（意味のない遊撃の往復などを防ぐ）。
- 行えない手（エンジンが拒否したもの）の評価は −∞。

## 2. 評価関数

盤面の評価値は「**自分の側の点数 − 相手の側の点数**」。大きいほど自分に有利。
片方の側の点数は、次の項目の合計。

| 項目 | 計算 | 重み |
|---|---|---|
| ライフ | ライフ × `life` | |
| ライフが少ない危険 | −(8 − ライフ) × `lowLife`（ライフが8以上なら0） | |
| 盤面のユニット | ユニットごとに `unitBase` ＋ 攻撃力 × `attack` ＋ 残り体力 × `health` ＋ 盾なら `shield` ＋ 射撃・貫通・先制・遊撃それぞれ `keyword` | 攻撃力・体力は常時効果・一時的な強化を含む今の値 |
| 手札 | 1枚ごとに `hand` ＋ コスト（6まで）× `handCost` | 相手の隠れた手札は仮のカードとして数える |
| 予備マナ | 予備マナの見込み × `reserve` | ラウンドの途中では「予備マナ＋使い残しの通常マナ」（次のラウンドに予備マナになる）。ラウンドの終わりでは予備マナ |
| リーダーの成長 | 成長済みなら `growth`。まだなら（進み具合 ÷ 必要な回数）× `growth` × 0.5 | リーダー2人それぞれ |
| 使えるリーダー能力 | 次のラウンドにコストを払えるリーダー能力1つごとに `leaderReady` | 払える目安 = 予備マナの見込み ＋ 次のラウンドの最大マナ |

### 2.1 重み

| 重み | 段階1（やさしい） | 段階2（ふつう・つよい） | 意味 |
|---|---|---|---|
| `life` | 1 | 1 | ライフ1の価値 |
| `lowLife` | 0.6 | 0.6 | ライフが8を下回ったときの追加の危険 |
| `attack` | 1 | 1 | 攻撃力1の価値 |
| `health` | 0.7 | 0.7 | 残り体力1の価値 |
| `shield` | 1.5 | 1.5 | 盾の価値 |
| `keyword` | 0.5 | 0.5 | 射撃・貫通・先制・遊撃それぞれの価値 |
| `unitBase` | 0.5 | 0.5 | ユニットが1体いること自体の価値 |
| `hand` | 1 | **0.7** | 手札1枚の価値 |
| `handCost` | 0 | **0.12** | 手札のカードのコスト1あたりの追加の価値（重いカードは持っている価値が高い） |
| `reserve` | 0.25 | **0.3** | 予備マナ1の価値 |
| `growth` | 3 | 3 | リーダーの成長の価値 |
| `leaderReady` | 0 | **0.8** | 次のラウンドに使えるリーダー能力1つの価値 |

段階2の値は、AI 同士の対戦で1つずつ値を変えて比べ、勝率が下がらない組み合わせを選んだ（各48試合。どの変更も段階2を上回らなかった）。

## 3. やさしい（easy・段階1）

- 評価関数の重みは **段階1**。
- 1.4 の評価値に、手ごとに **−1.5〜+1.5 の一様な乱数** を足してから、1.5 の方法で選ぶ（パスにも足す）。
  - 乱数は、試合の乱数とは別のシード（状態から決まる値）で作るので、試合の進行（シャッフルなど）には影響しない。
- 結果として、明らかに良い手（とどめを刺す、大きく得をする）は選ぶが、差の小さい場面では最善でない手もよく選ぶ。

## 4. ふつう（normal・段階2）

- 評価関数の重みは **段階2**。揺らぎはない。
- 1.4 の評価値が一番高い手を、1.5 の方法で選ぶ（1手読み ＋ 戦闘のシミュレーション）。
- 相手がこの後に打つ手は考えない。

## 5. つよい（hard・段階3）

段階2で良さそうな手に絞り、相手の隠れた情報を推測した「ありうる状況」の中で、**そのラウンドが終わるまで先を読んで** 選ぶ。
方式は「決定化したロールアウト」（相手の手札をいくつか推測して、それぞれの世界で先まで打ち進めてみる）。

### 5.1 手順

1. 全候補の手を段階2の方法（1.4）で評価する。
2. 評価の高い順に **6手**（`candidates`）を候補に残す。パスが入っていなければ加える。
   - 候補が1つだけなら、それを選ぶ。
   - 評価が +1000（その手で勝てる）の候補があれば、読まずにそれを選ぶ。
3. 「ありうる状況」を **3通り**（`worlds`）作る（5.2）。
4. 状況を1つずつ増やしながら、すべての候補について「その手を打った後、ラウンドが終わるまで打ち進めた結果」の評価値（5.3）を足していく。
   - 時間の上限を過ぎたら、その時点までの結果で決める。ただし、どの候補も少なくとも1回は評価する。
5. 平均の評価値が一番高い候補を選ぶ。差が 0.05 以内なら、段階2の評価（手順1）が高い方を選ぶ。

### 5.2 ありうる状況の作り方（決定化）

実際の状態を複製し、見えない部分を推測で埋める。

| 見えない部分 | 埋め方 |
|---|---|
| 相手の手札（公開されていないもの） | 相手のリーダー2人の勢力のカード（試遊版では各25種）から、1枚ずつ等しい確率でランダムに選ぶ。枚数は実際と同じ |
| 相手の山札 | 同じく、相手の勢力のカードからランダムに選ぶ。枚数は実際と同じ |
| 自分の山札 | 中身（自分のデッキの残り）はそのままで、順番だけシャッフルする |
| 乱数の状態 | 新しい値にする（「ランダムに」の効果の結果が状況ごとに変わる） |

相手が実際にどのデッキを使っているかは分からないので、「相手の勢力のどのカードでもありうる」として扱う。

### 5.3 1つの候補の評価（ロールアウト）

1. その状況で候補の手を適用する。
2. そのラウンドが終わるまで（または試合が終わるまで）、**双方が段階2（ふつう）の方針で交互に手を打つ**。
   - 各手番の判断は、その手番のプレイヤーから見た公開情報で行う（相手の推測した手札を覗いて打つわけではない）。
   - 1回のロールアウトは最大30手。時間の上限（5.4）の1.5倍を過ぎたら、そこで打ち切る。
3. 終わった状態を評価する。ラウンドが終わっていれば、その状態をそのまま評価する。途中で打ち切ったときは、「このまま戦闘になったら」の結果を評価する。

こうすることで、「自分の手に対する相手の応手」と「それに対する自分の次の手」まで反映される。
相手の最善の応手だけを1手読む方式も試したが、「その後に自分も動ける」ことが反映されず悲観的になり、ふつうより弱かった（勝率 44%）。

### 5.4 思考時間

| 使う場面 | 上限 |
|---|---|
| 試遊版（`app/`） | 1.5秒（1.5秒を過ぎると、ロールアウトの途中打ち切りと候補の評価の打ち切りが始まる） |
| 自動対戦の集計（`scripts/stats.ts`） | 0.8秒 |

試遊版では、AI の思考を Web Worker（画面とは別のスレッド）で行うので、考えている間も画面は固まらない。

## 6. 強さと速さの実測

AI 同士で、先手・後手とデッキの組み合わせを入れ替えて対戦させた結果（カードリスト v0.6 のころに測ったもの）。

| 組み合わせ | 勝率 | 試合 |
|---|---|---|
| ふつう 対 やさしい | ふつうの 56% | 216 |
| つよい 対 ふつう | つよいの 63% | 144 |
| 段階1（3段階に分ける前の AI）対 ランダムに手を選ぶプレイヤー | 段階1の 90%（20戦18勝） | 20 |

| 段階 | 1手あたりの思考時間（平均） |
|---|---|
| やさしい・ふつう | 約 8〜10ms |
| つよい | 約 170〜230ms（上限 0.8秒のとき） |

## 7. 既知の弱点と今後

| 弱点 | 内容 | 対策の案 |
|---|---|---|
| 1ラウンド先までしか見ない | 評価は「このラウンドの戦闘の結果」まで。次のラウンド以降にしか効かない手（ライフの回復、手札を増やす、重いカードのためにマナを残す）を低く見がち | 評価関数に「次のラウンドの展開」の見込みを加える。ロールアウトを次のラウンドの途中まで伸ばす |
| 学院のスペルを使いこなせない | ふつう同士の集計で学院のデッキが弱く出るのは、主にこのため（[balance.md](balance.md)）。つよい同士では差が縮まる | 上と同じ。スペルの枚数で強くなるカード（魔法の剣・魔導ゴーレムなど）の価値を評価に入れる |
| 相手のデッキを知らない | つよいは、相手の手札を「相手の勢力のどのカードでもありうる」として推測する。実際より強いカード・弱いカードも同じ確率で出てくる | 試合中に相手が使ったカードから、相手のデッキを推定する |
| 隠れたカードは仮のカード | 1手読みでは、相手の隠れた手札を王都の弓兵（2コスト 2/2）として数える | 勢力ごとの平均的なカードにする |
| マリガンがカード1枚ずつの判断 | 表はカード1枚ずつの値なので、手札の組み合わせ（軽いカードが1枚もない、同じカードが2枚ある）や、先手か後手かは見ない | 手札の組み合わせの特徴も表に入れる |
| 遅延の対象のよけ方 | 相手の遅延効果の予約は戦闘の予測に入るので、遊撃でよける手は評価されるが、「よけた先がより危ない」かは次のラウンドまで見ない | 上と同じ |

## 8. 調整のしかた

- 評価の重みは `engine/src/ai.ts` の `STAGE1_WEIGHTS`・`STAGE2_WEIGHTS`。`chooseAction(cat, state, player, { weights })` で差し替えて試せる。
- つよいの候補の数・状況の数・思考時間は `chooseAction` の `candidates`・`worlds`・`timeLimitMs` で変えられる。
- 強さの比較: `cd engine && npm run stats -- --games 4 --levels hard,normal --swap`（先手・デッキの偏りをなくすため、強さを入れ替えた試合も行う）。
