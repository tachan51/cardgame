## 1. 共通の前提

### 1.1 使ってよい情報

AI は人間と同じく、**自分から見える情報だけ** で判断する（ルール仕様書 4章）。

| 情報 | 使うか |
|---|---|
| 盤面・トラッシュ・除外・遅延ゾーン・リーダー・ライフ・マナ・予備マナ | 使う（公開情報） |
| 自分の手札 | 使う |
| 相手の手札のうち公開されたカード | 使う |
| 相手の手札（公開されていないもの）・相手の山札 | **使わない**。枚数だけ使う |
| 自分の山札 | 順番は使わない。つよいは「中身（自分のデッキ）」だけ使う（4.2） |

実装では、判断の前に状態を `publicView(state, 自分)` で公開情報だけにする。隠れたカードは仮のカード（**王都の弓兵 KN-03**。よくある安いユニットとして扱う）に置き換えてから、エンジンで先を試す（1.4）。

### 1.2 行動フェイズ以外の判断

| 場面 | 判断 |
|---|---|
| マリガン | やさしい: コスト5以上のカードをすべて戻す。ふつう・つよい: 相手の勢力ごとの「初手にあると勝ちやすいか」の表を使う（下記） |
| 山札の上から見て1枚選ぶ（データ検索など） | 一番コストの高いカードを選ぶ（3段階とも同じ） |

**ふつう・つよいのマリガン**（`engine/src/mulligan.ts`）

1. 手札の各カードの「見込み」を、表 `engine/src/mulligan-table.json` から引く。表の値は「そのカードが初手の4枚にあった試合の勝率が、同じ組み合わせ（自分のデッキ・相手のデッキ・先手か後手か）の平均より何ポイント高かったか」で、**相手の勢力ごと**に持つ。相手の勢力はリーダーで分かるので、相手の2つの勢力の値の平均を使う。
2. 表にないカードは、コストで決める（4コスト −1、5コスト以上 −4 から重いほど下げる）。
3. 代わりに引くカードの見込み = 自分の山札（自分のデッキの中身は知っている）の見込みの平均。これより悪いカードを戻す（余裕 0。0〜3ポイントを比べて一番よかった）。
4. 表は AI 同士の対戦（ふつう、双方マリガンなし）から作る: `cd engine && npm run mulligan-table`。見本デッキ同士の対戦に加えて、見本デッキに入っていないカードも表に載るように、勢力の組ごとに乱数で組んだ調査用のデッキも混ぜる。試合数の少ないカードの値は 0 に寄せる。カードやルールを変えたら作り直す。
5. 旧方式（コスト5以上を戻す）との比較（`npx tsx scripts/mulligan-ab.ts`。同じシードで方針を入れ替えた2試合ずつ。デッキは見本3つ＋表づくりに使っていない騎士団＋学院のデッキ）:

| 強さ | 余裕 | 新方式の勝率 | 戻した枚数（新 / 旧） |
|---|---|---|---|
| ふつう | 0（採用） | 53.0% ±1.9（2560試合） | 1.94 / 0.66 |
| ふつう | 1 | 52.3% ±1.9（2560試合） | 1.43 / 0.66 |
| ふつう | 2 | 51.7% ±1.9（2560試合） | 0.97 / 0.66 |
| ふつう | 3 | 51.5% ±1.9（2560試合） | 0.59 / 0.66 |
| つよい | 0 | 51.4% ±6.1（256試合） | 1.88 / 0.63 |

（この比較はカードリスト v0.7 のときのもの。表はカードリスト v0.8 で作り直した。）ふつうでは4デッキとも勝率が上がった（+1.5〜+10ポイント。表づくりに使っていないデッキは +1.5）。つよいは試合数が少なく、差は誤差の範囲。

### 1.3 候補の手

- 行動フェイズでは、合法手の一覧（`legalActions`）をすべて候補にする。カード × マス × 対象 × 強化するか、遊撃の移動先、起動能力、リーダー能力、パス。
- 強化・起動・リーダー能力のコストは、ルールどおり予備マナから先に払う（ルール仕様書 16.2）。支払いの内訳は候補に入らない。

### 1.4 1手の評価（1手読み）

候補の手 a ごとに、次の手順で「その手を打った後の評価値」を出す。

1. 公開情報の状態で a を実際に適用する（エンジンの `applyAction`）。
2. 結果に応じて評価する。
   - **試合が終わった**: 勝ちなら +1000、負けなら −1000、引き分けなら 0。
   - **効果の途中で選択が必要になった**（データ検索など）: 手を打つ前の評価に +0.5。
   - **ラウンドが終わって次のラウンドに進んだ**（相手がパスした後に自分もパスした場合など）: その状態をそのまま評価する（3章。「ラウンドの終わり」として扱う）。
   - **それ以外**: 「このまま戦闘になったら」を計算し（`previewCombat`）、その結果の状態を評価する。予約中の遅延効果は戦闘の前に必ず発動するので、先に発動させてから戦闘を計算する。

つまり、どの手も「**このラウンドの戦闘が終わった時点で、盤面がどうなっているか**」で比べる。相手がこの後に打つ手は考えない（つよいを除く）。

### 1.5 手の選び方

- 評価値が一番高い手を選ぶ。
- ただし、パス以外の手は **パスより 0.05 以上良いときだけ** 選ぶ。同じくらいならパスする（意味のない遊撃の往復などを防ぐ）。
- 行えない手（エンジンが拒否したもの）の評価は −∞。

## 2. 評価関数

盤面の評価値は「**自分の側の点数 − 相手の側の点数**」。大きいほど自分に有利。
片方の側の点数は、次の項目の合計。

| 項目 | 計算 | 重み |
|---|---|---|
| ライフ | ライフ × `life` | |
| ライフが少ない危険 | −(8 − ライフ) × `lowLife`（ライフが8以上なら0） | |
| 盤面のユニット | ユニットごとに `unitBase` ＋ 攻撃力 × `attack` ＋ 残り体力 × `health` ＋ 盾なら `shield` ＋ 射撃・貫通・先制・遊撃それぞれ `keyword` | 攻撃力・体力は常時効果・一時的な強化を含む今の値 |
| 手札 | 1枚ごとに `hand` ＋ コスト（6まで）× `handCost` | 相手の隠れた手札は仮のカードとして数える |
| 予備マナ | 予備マナの見込み × `reserve` | ラウンドの途中では「予備マナ＋使い残しの通常マナ」（次のラウンドに予備マナになる）。ラウンドの終わりでは予備マナ |
| リーダーの成長 | 成長済みなら `growth`。まだなら（進み具合 ÷ 必要な回数）× `growth` × 0.5 | リーダー2人それぞれ |
| 使えるリーダー能力 | 次のラウンドにコストを払えるリーダー能力1つごとに `leaderReady` | 払える目安 = 予備マナの見込み ＋ 次のラウンドの最大マナ |

### 2.1 重み

| 重み | 段階1（やさしい） | 段階2（ふつう・つよい） | 意味 |
|---|---|---|---|
| `life` | 1 | 1 | ライフ1の価値 |
| `lowLife` | 0.6 | 0.6 | ライフが8を下回ったときの追加の危険 |
| `attack` | 1 | 1 | 攻撃力1の価値 |
| `health` | 0.7 | 0.7 | 残り体力1の価値 |
| `shield` | 1.5 | 1.5 | 盾の価値 |
| `keyword` | 0.5 | 0.5 | 射撃・貫通・先制・遊撃それぞれの価値 |
| `unitBase` | 0.5 | 0.5 | ユニットが1体いること自体の価値 |
| `hand` | 1 | **0.7** | 手札1枚の価値 |
| `handCost` | 0 | **0.12** | 手札のカードのコスト1あたりの追加の価値（重いカードは持っている価値が高い） |
| `reserve` | 0.25 | **0.6** | 予備マナ1の価値 |
| `growth` | 3 | 3 | リーダーの成長の価値 |
| `leaderReady` | 0 | **0.8** | 次のラウンドに使えるリーダー能力1つの価値 |

段階2の値は、AI 同士の対戦で1つずつ値を変えて比べ、勝率が下がらない組み合わせを選んだ（各48試合。どの変更も段階2を上回らなかった）。

## 3. やさしい（easy・段階1）

- 評価関数の重みは **段階1**。
- 1.4 の評価値に、手ごとに **−1.5〜+1.5 の一様な乱数** を足してから、1.5 の方法で選ぶ（パスにも足す）。
  - 乱数は、試合の乱数とは別のシード（状態から決まる値）で作るので、試合の進行（シャッフルなど）には影響しない。
- 結果として、明らかに良い手（とどめを刺す、大きく得をする）は選ぶが、差の小さい場面では最善でない手もよく選ぶ。

## 4. ふつう（normal・段階2）

- 評価関数の重みは **段階2**。揺らぎはない。
- 1.4 の評価値が一番高い手を、1.5 の方法で選ぶ（1手読み ＋ 戦闘のシミュレーション）。
- ただし **即効の手**（追加の手番を得る手）は、その後の自分の手を1手読み、打たない場合も含めて一番良い評価をその手の評価にする（`quickFollow`。9章）。
- さらに、評価の上位6手（`planTop`）は「その手 → 相手がパス → 自分の次の手」まで読み、次の手と合わせて良くなる分をその手の評価に足す（`planFollow`。12章）。遅延で動かしておいて次の手番で当てる、のような組み合わせを選べる。
- 相手がこの後に打つ手は考えない。

## 5. つよい（hard・段階3）

段階2で良さそうな手に絞り、相手の隠れた情報を推測した「ありうる状況」の中で、**そのラウンドが終わるまで先を読んで** 選ぶ。
方式は「決定化したロールアウト」（相手の手札をいくつか推測して、それぞれの世界で先まで打ち進めてみる）。

### 5.1 手順

1. 全候補の手を段階2の方法（1.4）で評価する。
2. 評価の高い順に **6手**（`candidates`）を候補に残す。パスが入っていなければ加える。
   - 候補が1つだけなら、それを選ぶ。
   - 評価が +1000（その手で勝てる）の候補があれば、読まずにそれを選ぶ。
3. 「ありうる状況」を **3通り**（`worlds`）作る（5.2）。
4. 状況を1つずつ増やしながら、すべての候補について「その手を打った後、ラウンドが終わるまで打ち進めた結果」の評価値（5.3）を足していく。
   - 時間の上限を過ぎたら、その時点までの結果で決める。ただし、どの候補も少なくとも1回は評価する。
5. 平均の評価値が一番高い候補を選ぶ。差が 0.05 以内なら、段階2の評価（手順1）が高い方を選ぶ。

### 5.2 ありうる状況の作り方（決定化）

実際の状態を複製し、見えない部分を推測で埋める。

| 見えない部分 | 埋め方 |
|---|---|
| 相手の手札（公開されていないもの） | 相手のリーダー2人の勢力のカード（試遊版では各25種）から、1枚ずつ等しい確率でランダムに選ぶ。枚数は実際と同じ |
| 相手の山札 | 同じく、相手の勢力のカードからランダムに選ぶ。枚数は実際と同じ |
| 自分の山札 | 中身（自分のデッキの残り）はそのままで、順番だけシャッフルする |
| 乱数の状態 | 新しい値にする（「ランダムに」の効果の結果が状況ごとに変わる） |

相手が実際にどのデッキを使っているかは分からないので、「相手の勢力のどのカードでもありうる」として扱う。

### 5.3 1つの候補の評価（ロールアウト）

1. その状況で候補の手を適用する。
2. そのラウンドが終わるまで（または試合が終わるまで）、**双方が段階2（ふつう）の方針で交互に手を打つ**。
   - 各手番の判断は、その手番のプレイヤーから見た公開情報で行う（相手の推測した手札を覗いて打つわけではない）。
   - 1回のロールアウトは最大30手。時間の上限（5.4）の1.5倍を過ぎたら、そこで打ち切る。
3. 終わった状態を評価する。ラウンドが終わっていれば、その状態をそのまま評価する。途中で打ち切ったときは、「このまま戦闘になったら」の結果を評価する。

こうすることで、「自分の手に対する相手の応手」と「それに対する自分の次の手」まで反映される。
相手の最善の応手だけを1手読む方式も試したが、「その後に自分も動ける」ことが反映されず悲観的になり、ふつうより弱かった（勝率 44%）。

### 5.4 思考時間

| 使う場面 | 上限 |
|---|---|
| 試遊版（`app/`） | 1.5秒（1.5秒を過ぎると、ロールアウトの途中打ち切りと候補の評価の打ち切りが始まる） |
| 自動対戦の集計（`scripts/stats.ts`） | 0.8秒 |

試遊版では、AI の思考を Web Worker（画面とは別のスレッド）で行うので、考えている間も画面は固まらない。

## 7. 既知の弱点と今後

| 弱点 | 内容 | 対策の案 |
|---|---|---|
| 1ラウンド先までしか見ない | 評価は「このラウンドの戦闘の結果」まで。次のラウンド以降にしか効かない手（ライフの回復、手札を増やす、重いカードのためにマナを残す）を低く見がち | 評価関数に「次のラウンドの展開」の見込みを加える。ロールアウトを次のラウンドの途中まで伸ばす |
| 学院のスペルを使いこなせない | ふつう同士の集計で学院のデッキが弱く出るのは、主にこのため（[balance.md](balance.md)）。つよい同士では差が縮まる | 上と同じ。スペルの枚数で強くなるカード（魔法の剣・魔導ゴーレムなど）の価値を評価に入れる |
| 相手のデッキを知らない | つよいは、相手の手札を「相手の勢力のどのカードでもありうる」として推測する。実際より強いカード・弱いカードも同じ確率で出てくる | 試合中に相手が使ったカードから、相手のデッキを推定する |
| 隠れたカードは仮のカード | 1手読みでは、相手の隠れた手札を王都の弓兵（2コスト 2/2）として数える | 勢力ごとの平均的なカードにする |
| マリガンがカード1枚ずつの判断 | 表はカード1枚ずつの値なので、手札の組み合わせ（軽いカードが1枚もない、同じカードが2枚ある）や、先手か後手かは見ない | 手札の組み合わせの特徴も表に入れる |
| 遅延の対象のよけ方 | 相手の遅延効果の予約は戦闘の予測に入るので、遊撃でよける手は評価されるが、「よけた先がより危ない」かは次のラウンドまで見ない | 上と同じ |

## 8. 調整のしかた

- 評価の重みは `engine/src/ai.ts` の `STAGE1_WEIGHTS`・`STAGE2_WEIGHTS`。`chooseAction(cat, state, player, { weights })` で差し替えて試せる。
- つよいの候補の数・状況の数・思考時間は `chooseAction` の `candidates`・`worlds`・`timeLimitMs` で変えられる。
- 強さの比較: `cd engine && npm run stats -- --games 4 --levels hard,normal --swap`（先手・デッキの偏りをなくすため、強さを入れ替えた試合も行う）。

## 9. スペルを使うデッキの扱い（検討）

提案の電脳＋学院・騎士団＋学院（魔導ゴーレム・魔法の剣を3枚ずつ入れ、スペルを重ねて決めるデッキ）が、AI 同士の対戦で 28〜40% しか勝てなかった（[balance.md](balance.md)）。AI の扱いが原因かを調べた。

### 9.1 調べたこと

**手札に残りやすいカード**（ふつう。提案のデッキ 対 見本の騎士団＋学院、20試合ずつ。各ラウンドの始めに手札にあった平均枚数）

| デッキ | 多く残っていたカード |
|---|---|
| 提案: 電脳＋学院 | 魔力の矢 1.17 / 瞬間移動 0.81 / ホーミング魔弾 0.61 / 座標ズレ 0.57 / 魔法の剣 0.49 / 転送遅延 0.41 |
| 提案: 騎士団＋学院 | 魔力の矢 1.63 / ホーミング魔弾 0.66 / 陣形変更 0.46 / 瞬間移動 0.40 |

- マナはほぼ使い切っている（前のラウンドからの予備マナは 0.3〜0.4）。手札は 5.6〜5.7 枚と多め。
- 残るのは、安いがそのラウンドの戦闘の結果をあまり変えないスペル（移動・1ダメージ）と、即効のスペル。1手読みの評価では「手札1枚の価値」（約0.8）を上回らないと使わないため。

**評価を変えた試し**（ふつう同士、6デッキの総当たり 1組み合わせ 20試合。提案の電脳＋学院 / 騎士団＋学院の勝率。変える前は 28% / 38%）

| 試したこと | 重み（`AiWeights`） | 結果 |
|---|---|---|
| 使ったスペル1枚に価値を付ける（「使ったスペルの枚数」で強くなるカードを持っている割合に比例） | `spellCount` 0.4 / 0.8 / 1.2 | 33% / 35%、34% / 35%、27% / 38%（誤差の範囲） |
| 手札が5枚以上のとき、5枚目以降の価値を下げる | `handExtra` 0.5 / 0.2 | 31% / 40%、24% / 40%（誤差の範囲） |
| 即効の手は、その後の自分の手を1手読んで評価する | `quickFollow` | 26% / 40%。陣形変更の使用率 2%→40%、魔力還元 12%→25%、瞬間移動 45%→60% |

- `quickFollow` あり 対 なしを同じデッキで比べると（`AB_WEIGHTS='{"quickFollow":true}' npx tsx scripts/mulligan-ab.ts --policies smart,smart`、1500試合）、ありの勝率は **51.7% ±2.5**。すべてのデッキで少し良くなる（+1.7〜+5.2ポイント）が、思考時間は約2倍（6ms → 13ms）。
- どれも、提案の2デッキの勝率はほとんど変わらなかった。つよい（ロールアウトあり）でも 32〜40% なので、デッキそのものの弱さ（ユニットが少なく序盤に盤面を取られる）も大きいと考えられる。

### 9.2 改善の案（効果が大きそうな順）

| 案 | 内容 | 手間 | 期待 |
|---|---|---|---|

## 10. 自分のデッキ・相手のデッキで重みを変える（検討）

「自分のデッキの中身や相手の勢力によって評価の重みを変えると強くなるか」を調べた（`npx tsx scripts/weights-tune.ts`）。

**方法**: 段階2の重みを1つずつ変えた AI を、自分のデッキ D の側だけに使う。相手は見本デッキ3つ（ふつうの AI のまま）。同じシード・同じ席で「変えない D」と比べた勝率の差（ポイント）を出した。1マス 120組（相手3デッキ × 20シード × 先手後手）で、標準誤差は4〜5ポイント。`*` は差が標準誤差の2倍より大きいもの。

| 重みの変え方 | ドローンと魔法の弾幕（電脳＋学院） | 壁の奥から大魔法（騎士団＋学院） | 号令で押し切る（騎士団＋電脳） | 提案2: 電脳＋学院 | 提案2: 騎士団＋学院 |
|---|---|---|---|---|---|
| ライフ×1.5 | -2 | -8* | -0 | +2 | +0 |
| ライフ×0.6 | -2 | -3 | -3 | +3 | -4 |
| 攻撃力×1.4 | +2 | +0 | -3 | +4 | -1 |
| 体力×1.4 | -2 | +0 | -2 | +5 | +0 |
| ユニット×2 | +1 | -2 | +0 | +5 | +2 |
| 手札×0.6 | -4 | -1 | +2 | +5 | +3 |
| 手札×1.5 | -4 | +1 | -1 | +7* | -0 |
| 予備マナ×0.3 | +3 | -3 | -3 | -0 | +1 |
| 予備マナ×2 | +0 | +3 | +4 | +7* | +6 |
| 成長×2 | +4 | -3 | +3 | +0 | +3 |

- ほとんどのマスは誤差の範囲だった。50マスを2倍の基準で見ているので、偶然で2〜3マスは `*` が付く。
- 相手のデッキ別に分けると（1マス40組）、`*` が付いたのは5マスだけで、決まった傾向はなかった。例えば「提案の電脳＋学院が、ライフ×1.5 で見本の電脳＋学院に +9」「手札×0.6 で見本の電脳＋学院が同型に −13」など。
- 目立つ傾向は **予備マナ×2**（`reserve` 0.3 → 0.6）で、5デッキ中4つがプラスだった。デッキによらず効く可能性があるので、同じデッキで直接比べた（`AB_WEIGHTS='{"reserve":0.6}' npx tsx scripts/mulligan-ab.ts --policies smart,smart`、1500試合）。変えた側の勝率は **52.2% ±2.5** で、5デッキすべてで +2〜+6 ポイントだった。

**考え**

- 「デッキ・相手ごとの重みの表」は、今の試合数では差を見分けられない（1組み合わせで ±5ポイント以内）。見分けるには1マス数千試合が要り、デッキを変えるたびに作り直しになる。作っても、たまたま良かった値を拾う危険が大きい。
- 効果がはっきりしているのは、デッキによらない調整（予備マナの重み）と、読みの深さの改善（9章の `quickFollow`）。どちらも +2 ポイントほど。
- デッキに合わせたいなら、重みを変えるより、デッキの中身から決まる値を評価に入れるほうが筋がよい。例: 9章の案 D（手札に持っておく価値をカードごとに求める）。マリガンの表と同じく、相手の勢力ごとに持てる。
- 次にやるなら、(1) 予備マナの重みを 0.6 にする（全体の調整）、(2) 案 D を相手の勢力ごとの表として作る、の順がよいと考える。
- (1) は採用した（`STAGE2_WEIGHTS.reserve` = 0.6）。

## 11. 手札の価値の表（9章の案 D）の試し

**作り方**（`npm run hand-table`、`engine/src/hand-table.json`）: ふつうの AI 同士で 2790試合（見本デッキと調査用のデッキ）を行い、各ラウンドの始めの状態を 51540件集めた。「今の評価値（手札は一律の価値）」と「手札の各カードの枚数」から勝ち負けをロジスティック回帰で予測し、カードの係数を評価値の単位に直したものを「手札1枚の価値の補正」とした（相手の勢力ごと、±2 で打ち切り）。

- 補正が小さく出たのは、崩落の予言・EMPグレネード・禁書の閲覧・魔力還元・データ検索・魔女の聖水など（持っているより使ったほうがよい）。大きく出たのは、主力のユニットの多く（+2 で打ち切り）。

**結果**（表を使う側 対 使わない側。同じデッキ・同じシード、見本3つ＋提案の2デッキ、1500試合）

| 表の使い方 | 表を使う側の勝率 |
|---|---|
| そのまま | 44.6% ±2.5 |
| 勢力ごとに平均を 0 にそろえる | 42.3% ±2.5 |
| 負の補正だけ使う（使ったほうがよいカードだけ下げる） | 46.1% ±2.5 |
| 0.3倍に弱める | 48.8% ±2.5 |

- どれも弱くなったので、**採用しない**（`handTable` は既定では働かない。表とスクリプトは残す）。
- 原因の見立て: 回帰の係数は「そのカードが手札にある試合は勝ちやすいか」で、「持っておくのと使うのとでどちらが得か」ではない。強いユニットを引いた試合は勝ちやすいので、ユニットの係数が大きく出て、AI が出さずに抱えてしまう。逆に、負けている試合で残りやすいカード（盤面を取られているときに使いどころのないスペル）の係数は小さく出るが、それは原因ではなく結果である。
- 手札の価値をカードごとに変えるなら、観察データの回帰ではなく、値を少しずつ変えて対戦させ、勝率が上がる方向に動かす方法（重みの調整と同じやり方。1回の比較に1500試合ほど要る）が必要。手間が大きいわりに、10章の結果から効果は数ポイントと見込まれる。
- 読みを深くする（9章の案 B・C）ほうが、スペルの使いどころを直接よくできる見込みがある。

## 12. 次のラウンドまで見る（案 B）・組み合わせを読む（案 C）

### 12.1 案 C: 組み合わせを読む（採用）

1手読みの評価の上位6手について、「その手 → 相手がパス → 自分の次の手（全候補）」まで読み、一番良い次の手と合わせた評価がその手だけの評価より高ければ、差の `planFollow` 倍を足す（`engine/src/ai.ts` の `planAhead`）。つよいのロールアウトの中（相手・自分の応手）では使わない。

| 設定 | 使う側の勝率（同じデッキ・同じシード。見本3デッキ） |
|---|---|
| `planFollow` 0.5 | 51.1% ±5.2（360試合） |
| `planFollow` 1 | 54.9% ±5.1（360試合）→ 確認 **54.0% ±3.0**（1080試合） |
| `planFollow` 1、上位10手 | 54.2% ±3.0（1080試合。6手と変わらず、時間がかかる） |

- デッキ別（1080試合）: 召喚と魔法の総力戦（電脳＋学院）+6.3、壁の奥から大魔法（騎士団＋学院）+15.1、号令で押し切る（騎士団＋電脳）+2.5 ポイント。スペルや遅延の多い学院のデッキほど効く。
- **採用した**（`planFollow` 1、`planTop` 6。ふつう・つよい）。ふつうの思考時間は1手あたり約 34ms、つよいは約 330ms（上限 0.8秒のとき）。

### 12.2 案 B: 次のラウンドまで見る（採用しない）

| 試したこと | 使う側の勝率 |
|---|---|
| つよいのロールアウトを、次のラウンドの終わりまで伸ばす（`rolloutRounds` 2） | 33.7% ±7.7（つよい同士 144試合） |
| 同上、思考時間を3倍（2.4秒）にして | 38.5% ±7.9（つよい同士 144試合） |
| 評価で、次のラウンドのマナで使えない手札の価値を 0.6倍 / 1.3倍（`unplayableHand`） | 51.3% / 50.4% ±4.2（ふつう同士 540試合） |

- ロールアウトを伸ばすと、時間を増やしても大きく弱くなった。見立て: ロールアウトは両者をふつうの方針で打ち進めるので、先が長いほど雑な手が積み重なり、候補の手の違いが結果に表れにくくなる。また、相手の隠れた手札は「相手の勢力のどのカードでもありうる」として推測しているので、先が長いほど推測の誤差が大きくなる。
- 評価に次のラウンドの使いやすさを入れる方法は、誤差の範囲だった。
- どちらも既定では働かない（`rolloutRounds` 1、`unplayableHand` なし）。次のラウンドの価値を入れるなら、ロールアウトより、組み合わせの読み（案 C）を2手先に広げる方向がよいと考える。

## 13. さらなる改善案の検討

5つの案を、調整用の設定として実装して試した（どれも既定では働かない）。比べ方は、同じデッキ・同じシードで、片方だけ設定を変えた AI の勝率（`AB_WEIGHTS='{...}' npx tsx scripts/mulligan-ab.ts --policies smart,smart`。見本3デッキ）。

| 案 | 設定 | ふつう同士（720試合） | つよい同士（216試合） |
|---|---|---|---|
| 予備マナと現在マナの重みを分ける | `mana`（使い残している通常マナ1の価値。今は予備マナと同じ 0.6）を 0.3 / 1.0 | 48.2% / 50.6% ±3.7 | — |
| 数ラウンドパスが続いた場合の評価値を使う | `passRounds` 2（双方がパスを続けて2ラウンド先まで進めた評価）を `passBlend` 0.3 / 0.5 の割合で混ぜる | 46.6% / 47.4% ±3.6 | — |
| 候補に似たような手を入れない | `diverse`（同じカードの置き場所・対象違いは、評価の一番高いものだけを候補にする。組み合わせの読みの上位6手と、つよいの候補） | 50.0% ±3.7 | 50.9% ±6.7 |
| 相手の手札に加わったカードを覚えておく | `remember`（生成した・盤面から手札に戻したカードは、相手にも中身が分かるものとして扱う） | 49.9% ±3.7 | 46.1% ±6.6（下と合わせて） |
| 「つよい」で相手の手札を推測する | `inferHand` 2（相手がすでに使ったカードは、残りの枚数ぶん推測で出やすくする） | — | （上と合わせて） |

- どれも、はっきりした改善は見られなかった（差は誤差の範囲か、少し悪い）。**採用しない**。
- 予備マナと現在マナ: 現在マナの価値を下げると少し悪く（48.2%）、上げても変わらない。使い残した通常マナは次のラウンドに予備マナになるので、同じ価値でよいと考えられる。
- パスを続けた先の評価: 少し悪くなった。パスを続けると、双方とも手札をまったく使わない前提になり、ユニットの多い側が過大に評価される。
- 似た手を入れない: ふつうでは変わらない。つよいでは、学院のデッキで +6〜+8、騎士団＋電脳で −8 と分かれたが、試合数が少なく誤差の範囲。置き場所だけが違う手でも、どこに置くかで戦闘の結果が大きく変わる場面があるので、1つにまとめると良い手を落とすことがある。
- 覚える・推測する: 生成したカードや手札に戻したカードが相手の手札にある場面は少なく、ふつうではほぼ影響がない。つよいでの推測は、見本デッキが同じカードを3枚ずつ入れているので理屈では当たりやすくなるはずだが、試合数の範囲では良くならなかった。推測の状況は3通りしか作らないので、推測の精度よりも、状況の数の少なさのほうが結果を左右していると考えられる。
- つよいの比較は 216試合で ±6.7 ポイントぶれる。つよいの小さな改善（数ポイント）を確かめるには 1000試合以上（数時間）が必要。

### 13.1 追加の検証

| 案 | 設定 | 結果 |
|---|---|---|
| 予備マナの価値を下げ、現在マナの価値を上げる | `reserve` 0.3・`mana` 0.9 | 51.4% ±3.7（ふつう同士 720試合） |

| 同上（確認） | `reserve` 0.3・`mana` 0.9 | **49.2% ±1.8**（ふつう同士 2880試合） |

## 14. 終盤に一気に攻めるデッキの扱い（検討）

終盤に一気に攻めるデッキ（魔導ゴーレム・魔法の剣など）を AI がうまく扱えるように、2つの案を実装して試した（どれも既定では働かない）。比べ方は、同じデッキ・同じシードで片方だけ設定を変えた AI の勝率（ふつう同士。見本3デッキ＋提案の電脳＋学院・騎士団＋学院（魔導ゴーレム・魔法の剣を3枚ずつ）の5デッキ）。

**① 攻め・守りの役割で重みを切り替える**（`role`）: 自分と相手のデッキの「終盤の強さ」（コスト。コストが下がるカード・スペルの枚数で強くなるカードは上乗せ。相手は公開されたカードと勢力の平均から見積もる）を比べ、自分のほうが終盤に強ければライフ・体力・手札・予備マナを重く、攻撃力を軽くする。弱ければ逆。

**② 決めに行く探索**（`burstDepth`・`burstMana`・`burstLife`・`burstWidth`）: 相手がパスし続けるとして、自分の手を最大4手先まで読む（各段で評価の高い4本の手順を残す）。良い手順が見つかれば、その1手目の評価を上げる。発動の条件は、自分が使えるマナ（通常マナ＋予備マナ）か相手のライフで決められる（省略時は毎回）。

| 設定 | 使う側の勝率 |
|---|---|
| ① `role` 0.3 | 48.4% ±3.1（1000試合。5デッキすべてマイナス） |
| ① `role` 0.6 | 48.0% ±3.1（1000試合。5デッキすべてマイナス） |
| ② 毎回探索（`burstDepth` 4） | 52.8% ±3.1（1000試合。5デッキすべてプラス）→ 確認 **50.2% ±2.2**（2000試合） |
| ② マナ6以上か相手のライフ10以下のときだけ（`burstMana` 6、`burstLife` 10） | 51.1% ±3.1（1000試合） |
| ② 毎回探索（つよい同士） | 46.9% ±8.2（つよい同士 144試合） |

- ① は5デッキすべてで少し悪くなった。採用しない。デッキの中身から決めた「どちらが終盤に強いか」が実際の展開と合わないことがあるうえ、守りに寄せると盤面を取る判断が遅れると考えられる。
- ② は最初の1000試合ではすべてのデッキでプラスに見えたが、2000試合で確かめると 50.2% で差はなかった（合わせて 3000試合で約 51%、誤差の範囲）。思考時間が約2倍になるので、採用しない。つよい同士でも 46.9% ±8.2（144試合）で、良くならなかった。
  - 「相手がパスし続ける」前提は楽観的で、読んだ手順どおりに進まないことが多い。組み合わせの読み（12章、2手先）で取れる分は、すでに取れていると考えられる。
- 終盤型のデッキの弱さは、読み方よりも、デッキの序盤の弱さ（ユニットが少ない）によるところが大きいと考えられる。

## 15. パスの価値を高く見積もる（検討）

パスすると相手に先に行動させ、自分はそれに対応して動ける。この価値を評価に入れる2つの形を試した（どれも既定では働かない）。比べ方は、同じデッキ・同じシードで片方だけ設定を変えた AI の勝率（ふつう同士、見本3デッキ、720試合、±3.7）。

| 形 | 設定 | 変えた側の勝率 |
|---|---|---|
| パスの評価に一律のボーナスを足す | `passBonus` 0.3 / 0.7 / 1.5 | 47.7% / 49.2% / 49.3% |
| 相手の取れる行動の多さに応じたボーナス（相手の行動が3つ以上で最大。相手がすでにパスしていて自分のパスで戦闘になるときは 0） | `passReact` 0.7 / 1.5 | 49.7% / 49.7% |

- 相手の取れる行動: 手札のうち払えそうな枚数（1枚2マナとして、通常マナ＋予備マナで払える分）、遊撃がまだ使えるユニット、払える起動能力、払えるリーダー能力の数。
- 一律のボーナスは、相手が何もできない場面でもパスを選びやすくなり、少し悪くなった。相手の行動の多さに応じた形はその損がなくなったが、良くもならなかった。どちらも採用しない。
- 見立て: ふつうは相手の手を読まないので、パスした後に「相手の手に対応して得をする」場面を、パスの時点では確かめられない。ボーナスは、実際に対応して得をする場面かどうかに関係なく足されるので、良い場面と悪い場面が打ち消し合っていると考えられる。
- つよいは、ロールアウトでパスした後の相手の手と自分の応手まで読むので、この価値はすでに一部入っている。
