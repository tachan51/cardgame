## 1. 概要

| 項目 | 内容 |
|---|---|
| タイトル | 未定（仮称: *Project Cardgame*） |
| ジャンル | 1対1 デッキ構築型デジタルカードゲーム（対AI専用） |
| 対戦形式 | プレイヤー vs AI。双方が自作デッキを持ち寄って対戦 |
| ゲームシステム | ラウンド制・交互行動（Legends of Runeterra 型）＋ 4列×前後2段のレーン配置 ＋ ラウンド終了時の同時戦闘 ＋ 2人のリーダーのコンビ |
| プラットフォーム | 試遊版: Webブラウザ / 製品版: Godot（PC想定） |
| 制作体制 | 個人/趣味制作 |
| プレイ時間 | 1試合 10〜15分【仮】 |

### 1.1 コンセプト（一文）

**「異なる世界の少年たちが手を組み、4本のレーンでぶつかり合う。配置の読み合いで勝つカードゲーム」**

### 1.2 ゲームの面白さの核

1. **配置の読み合い** — 双方が1手ずつ交互にユニットを置いていく。相手の配置を見てから置くか、先に置いて主導権を取るか。どのレーンのどの段に置くかが勝負を分ける。
2. **ラウンド終了時の同時戦闘** — 攻撃する側・守る側の区別はなく、ラウンドの最後に全レーンで一斉にぶつかる。組み上がった盤面の結果がそのまま出る。
3. **勢力ごとに違う世界観と戦い方** — 世界そのものが違う勢力同士が戦う。勢力によって「前列の壁で守る」「後列から撃つ」「空きマスを利用する」など、盤面の使い方がはっきり異なる。
4. **2人のリーダーが手を組むデッキ構築** — 各勢力のリーダーである少年2人を選んでコンビを組み、その2つの世界のカードでデッキを作る。「どの2人を組ませるか」がデッキの個性になる。
5. **少年たちの物語** — 世界の違う少年たちが、ライバルとして競い合い、ときに友情を育む。対戦相手のAIも少年たちのコンビとして登場する。
6. **待ち時間ゼロの対AI戦** — マッチング待ちや対人のストレスがなく、自分のペースで遊べる。

---

## 2. ターゲットとプレイ体験

- **ターゲット**: デジタルカードゲーム経験者（LoR、Hearthstone、MTG Arena等）で、対人戦の緊張や時間拘束を避けたい人。盤面を組み立てるタイプのゲーム（オートバトラー、タクティクス系）が好きな人。
- **提供したい体験**
  - 自分の配置が噛み合って、同時戦闘で一気に押し切ったときの気持ちよさ
  - 賢く動くAIとの読み合いで勝つ達成感
  - 負けたときに「配置やデッキをこう直そう」と思える納得感（AIが理不尽なズルをしない）

## 3. 世界観

### 3.1 基本設定

**複数の異なる世界が「狭間（はざま）」と呼ばれる場所で交わり、それぞれの世界の軍勢が衝突する**【仮】。

- 勢力ごとに **時代・技術水準・美術スタイル・カード名の付け方まで** 大きく変える。
  - 例: ファンタジーの騎士団とサイバーパンクの電脳都市が同じ盤面で戦う。
- 世界観の違いを **ゲームの仕組み上の違い（盤面の使い方）** と一致させ、見た目だけでなく遊び方でも個性が出るようにする。
- 異世界同士が交わる理由・「狭間」の正体は、少年たちの物語の軸にする（製品版以降）。

### 3.2 勢力案【仮】

勢力は **できるだけ多く作り、継続的に追加していく**（3.4）。試遊版では **王国騎士団・電脳都市・魔法学院の3勢力** を実装する（野生の密林は試遊版の後に回す）。以下は最初の候補。

> 候補の詳しい一覧と、試遊版の勢力を選ぶための比較は [勢力案一覧（factions.md）](factions.md) にまとめている。

| 勢力（仮称） | 世界観 | 盤面での戦い方 | 試遊版 |
|---|---|---|---|
| 王国騎士団 | 中世ファンタジー。剣と盾、騎士道 | **前列の壁**。体力の高い前列ユニットと、左右隣の味方を強化する効果 | **○** |
| 電脳都市 | サイバーパンク。ハッカー、ドローン、企業傭兵 | **後列からの射撃**と、敵ユニットを別のマスへ動かす「ハッキング」 | **○** |
| 百鬼夜行 | 和風妖怪。夜の都、怪異 | **空きマスと死**を利用する。倒れると化けて出る、空いたマスに湧く | — |
| 深淵の眷属 | コズミックホラー / 深海 | **大型ユニット**。前後2マスを占有する巨体、相手に「狂気」を与える | — |
| 野生の密林 | 熱帯の密林。猛獣と、獣と共に生きる部族 | **群れと連携**。同じレーンの前後に並べると強くなる | 試遊版の後 |
| 魔法学院 | 空に浮かぶ魔法使いの学園 | **スペルと遅延**。スペルを連発し、相手に予告してから放つ大魔法でマスを狙い撃つ | **○** |
| 星間艦隊 | 宇宙SF | レーン全体に効く艦砲射撃、次の手番に着弾する遅延攻撃 | — |

このほかの候補: 砂漠の王朝（古代エジプト風）、蒸気帝国（スチームパンク）、海賊団、終末世界（ポストアポカリプス）、夢の国（童話）など。

### 3.3 リーダー（少年たち）

- **各勢力に1人ずつ、リーダーとなる少年がいる。** 少年はその世界の代表であり、勢力の戦い方を体現するキャラクター。
- 少年たちは異なる世界から「狭間」に呼ばれ、**ライバルとして競い合い、ときに友情を育む**。
- **1デッキ = 2人の少年が手を組むコンビ。** プレイヤーは2人のリーダーを選び、その2勢力のカードでデッキを作る。
- 少年同士の関係（ライバル、親友、因縁など）を設定し、組み合わせによって試合前後の掛け合いや、コンビ専用の演出が変わるようにする（製品版以降）。
- 対戦相手のAIも「2人の少年のコンビ」として登場する。AIデッキにキャラクター性が出て、「今日はあのコンビと戦う」という動機になる。

| 勢力（仮称） | リーダー像の例【仮】 |
|---|---|
| 王国騎士団 | 見習い騎士の少年。まっすぐで仲間思い、盾で皆を守る |
| 電脳都市 | 天才ハッカーの少年。皮肉屋だが実は寂しがり |
| 野生の密林 | 獣に育てられた少年。言葉少なで野性的 |
| 魔法学院 | 落ちこぼれ魔法使いの少年。努力家で負けず嫌い |

### 3.4 勢力の追加方針（拡張方針）

- **カードの追加は、新しい勢力（＝新しい世界と新しい少年）の追加を中心に行う。** 既存勢力へのカード追加は、バランス調整や新勢力との組み合わせの補強に留める。
- 新勢力を1つ追加するたびに、既存のすべての少年との **新しいコンビ** が生まれる（勢力数 n に対してコンビは n×(n−1)/2 通り）。1つの追加で遊びの幅が大きく広がる。
- 新勢力には **盤面の新しい使い方** を1つ持たせる（例: 巨体、空きマス、地形）。見た目だけの差にしない。
- 個人制作で勢力を増やし続けられるよう、1勢力あたりの制作量を一定にする（9. コンテンツ規模）。

## 4. ゲームルール（コア）

> 数値は暫定値（バランス調整で変わる前提）。詳細なルールは [rules.md](rules.md) で定める。

### 4.1 勝利条件

- 相手の **ライフ（初期20）** を0にする。
- 山札が尽きた状態でドローが必要になったプレイヤーは敗北。
- 同時戦闘で双方のライフが同時に0以下になった場合は、**ライフのマイナスが大きい側の負け**（例: −3 と −1 なら −3 の側が負け）。
  - マイナスの値もまったく同じ場合は **引き分け**。

### 4.2 盤面

各プレイヤーが **4列（レーン）× 前列・後列の2段 = 8マス** を持つ。レーンは相手の同じ番号のレーンと向かい合う。

```
            レーン1   レーン2   レーン3   レーン4
          ┌───────┬───────┬───────┬───────┐
 相手 後列 │       │       │       │       │
          ├───────┼───────┼───────┼───────┤
 相手 前列 │       │       │       │       │
          ╞═══════╪═══════╪═══════╪═══════╡  ← 戦線
 自分 前列 │       │       │       │       │
          ├───────┼───────┼───────┼───────┤
 自分 後列 │       │       │       │       │
          └───────┴───────┴───────┴───────┘
```

- 1マスにユニットは1体まで。
- **前列**: 戦闘で敵とぶつかる。攻撃役・壁役を置く場所。
- **後列**: 同じレーンの前列が倒れない限り、通常の攻撃からは守られる。支援役・射撃役を置く場所。
- **一度置いたユニットは、基本的に移動できない。** 例外は、キーワード（遊撃）・スペル・能力による移動だけ（4.6）。
  - 以前は後列から前列への「前進」を基本アクションにしていたが、v0.18 で廃止した。

### 4.3 ラウンドの流れ

攻撃権はなく、**毎ラウンドの終わりに双方のユニットが同時に戦う**。

```
[ラウンド開始]
  ├─ 双方: 最大マナ+1（上限10）
  ├─ 双方: 前のラウンドで使い残した通常マナを「予備マナ」に加える（上限なし）
  ├─ 双方: 通常マナを全回復
  ├─ 双方: 1枚ドロー
  ├─ 先手トークンが一方に移る（毎ラウンド交互）
  │
[配置・行動フェイズ]  ← 先手トークンを持つ側から交互に1アクション
  │   アクション = ユニット配置 / スペル使用 / 遊撃による移動 / リーダー能力の使用 / 追加能力の使用 / パス
  │   ・双方が連続でパス → 戦闘フェイズへ
  │
[戦闘フェイズ]  ← 全レーンで同時に戦闘（4.4）
  │
[ラウンド終了]
  └─ 「ラウンド終了時」効果の処理
```

- 初期手札: 4枚。開始時に任意枚数を1回だけ引き直し（マリガン）可能。
- **先手トークン**: そのラウンドで最初に行動できる権利。先に置けば好きなマスを取れるが、相手に配置を見られてから対応される。先手・後手どちらにも利点がある作りにする。

#### マナと予備マナ

マナは **通常マナ** と **予備マナ** の2種類。

| | 通常マナ | 予備マナ |
|---|---|---|
| 初期値 | 0（第1ラウンド開始時に最大値1になる） | 0 |
| 増え方 | ラウンド開始時に最大値+1（上限10）して全回復 | ラウンド開始時、最大マナ+1の **後** に、前のラウンドで使い残した通常マナがすべて加算される |
| 上限 | 10 | なし |
| 使い道 | カードのプレイ（ユニット配置・スペルなど）、**および予備マナの代わり** | **リーダー能力** と **カードの追加能力** のみ |
| 翌ラウンドへの持ち越し | しない（毎ラウンド全回復） | する（使うまで貯まり続ける） |

- **スペルやユニットのプレイには通常マナしか使えない。** 予備マナで手札のカードを出すことはできない。
- 逆に、**リーダー能力や追加能力のコストは、予備マナ・通常マナのどちらでも（組み合わせても）支払える。**
- 予備マナに上限はない（v0.18。以前は最大マナと同じ値を上限にしていた）。
- 先手・後手による予備マナの補償はない。双方とも予備マナ0から始める。
- そのため「今ラウンドはカードを出さずにマナを残し、次のラウンド以降にリーダー能力を連発する」「カードを出し切って、予備マナだけでリーダー能力を使う」といった、マナの使い分けの判断が生まれる。

**追加能力**: カードに付いている、予備マナ（または通常マナ）を払って使う追加の効果。形は2種類を想定【仮】。

| 形 | 内容 | 例 |
|---|---|---|
| 強化 | カードをプレイするときに、追加で支払うと効果が強くなる | 「火球（3マナ）: ユニット1体に3ダメージ。強化（予備2）: さらに同じレーンの後列にも2ダメージ」 |
| 起動 | 盤面にいるユニットが、自分の手番に支払って使う能力（1アクション） | 「見張り塔の射手: 起動（予備1）: このラウンド射撃を得る」 |

### 4.4 戦闘の解決

戦闘は **全レーン同時** に解決する（ダメージをすべて計算してから一斉に適用する）。どちらが先に殴るかという有利不利をなくし、結果を予測しやすくする。

**攻撃の対象（各レーン内）**

| 攻撃するユニット | 攻撃対象 |
|---|---|
| 自分の前列 | 同じレーンの **敵の前列** → 空なら **敵の後列** → それも空なら **敵本体（ライフ）** |
| 自分の後列 | 通常は攻撃しない。「射撃」を持つユニットのみ、前列と同じルールで攻撃する |

- 前列同士は **互いに同時にダメージを与え合う**。
- 前列が空いたレーンでは後列がむき出しになり、前後とも空いたレーンは本体まで素通しになる。**前列の壁をどのレーンに置くか** が守りの判断になる。
- 前列がいる間に後列を狙えるのは、「貫通」（前列ユニットを倒した余剰ダメージが後列へ）などのキーワードやスペルのみ。
- 体力が0以下になったユニットは戦闘後にまとめて破壊される。
- 前列のユニットが破壊されても、後列のユニットは自動では前に出ない。

**例**（レーン2）

```
 相手 後列 : 弓兵 2/1 [射撃]
 相手 前列 : （空き）
 自分 前列 : 騎士 3/4
 自分 後列 : 僧侶 0/2
```

→ 騎士は相手の前列が空なので、相手の後列の **弓兵に3ダメージ**（弓兵は破壊）。弓兵も同時に射撃で自分の前列の **騎士に2ダメージ**（騎士は 3/2 で生き残る）。僧侶は攻撃しない。本体へのダメージはなし。

もしこのレーンの相手側が前列・後列とも空なら、騎士の3ダメージはそのまま **相手本体** に入る。

### 4.5 カードの種類

| 種類 | 説明 |
|---|---|
| ユニット | 盤面のマスに配置する。配置後は原則として移動しない。攻撃力/体力/キーワード能力を持つ。前列・後列のどちらにも置ける（配置制限はない） |
| スペル | 使い切りの効果。自分の手番に使用し、**即時に解決** する。味方・敵のユニットを移動させるスペルもここに含む |
| （分類）中立カード | ユニット・スペルのうち、どの勢力にも属さず、どのデッキにも入れられるもの |
| リーダー（カードではない） | 各勢力の少年。デッキとは別枠で2人を選ぶ。盤面には出ず、常にリーダーゾーンにいる（4.8） |
| 地形（将来） | マス（枠）に置き、そのマスに地形効果を与える。例: 「城壁」＝このマスのユニットは体力+2、「沼地」＝このマスのユニットは前進できない |
| 【検討】設置物 | マスに置く罠・建物（試遊版では見送り可） |

- 攻撃権を廃止し戦闘タイミングが固定になったため、v0.1にあったスペル速度とスタック（割り込み処理）は **試遊版では採用しない**。すべての効果を即時解決にしてルールと実装を単純にする。
- 相手の行動に反応する要素は、必要になったら「伏せて置き、条件を満たすと発動する罠」として追加を検討する。

### 4.6 キーワード能力の例【仮】

| キーワード | 効果 |
|---|---|
| 射撃 | 後列からでも攻撃できる（攻撃対象の順番は前列ユニットと同じ） |
| 貫通 | 敵の前列を倒した余剰ダメージが、同じレーンの敵後列（空なら本体）へ |
| 挑発（試遊版の後） | 隣のレーンの敵前列ユニットの攻撃を、このユニットに引き付ける |
| 巨体（試遊版の後） | 同じレーンの前後2マスを占有する |
| 遊撃 | 自分の手番のアクションとして、自分の盤面の任意の空きマスへ移動できる。1ラウンドに1回 |
| 押し出し（試遊版の後） | 配置時、同じレーンの敵前列ユニットを隣のレーンの空きマスへ動かす |
| 先制 | 戦闘で、先制を持たないユニットより先にダメージを与える |
| 盾 | 次に受けるダメージを1回だけ0にする |
| 遅延 | 使ってから発動まで、通常は相手に1回だけ手番を与える効果。使ったときには遅延の付いていない効果だけが発動し、遅延の付いた効果は **自分の次の手番の始め** に発動する（発動そのものがその手番の行動になる）。相手は予告を見て、移動・守るスペルなどで対策できる（例: 「マスを1つ指定。遅延: そのマスのユニットを破壊」） |
| 即効 | 使った後、相手に行動権を渡さずに追加の手番を得る。即効と遅延を両方持つカードは、追加の手番で遅延が発動する（実質相殺） |

### 4.7 デッキ構築ルール

- デッキ枚数: **40枚**、同名カードは **3枚まで**【仮】
- **リーダー2人を選び、その2勢力のカードと中立カード（試遊版にはない）でデッキを作る**（例: 王国騎士団の少年＋電脳都市の少年）。
- 各勢力のリーダーは1人なので、コンビは必ず異なる2勢力の組み合わせになる。
- カードの比率に制限はない。一方の勢力のカードだけで40枚にしてもよい（その場合も、もう一方の少年はリーダー能力で力を貸す）。
- **中立カード**: どの勢力にも属さず、どのデッキにも入れられるカード。「狭間」そのものに由来するカードとして、試遊版から用意する。

### 4.8 リーダーのルール【仮】

少年たちは盤面で戦うユニットではなく、**盤面の外から仲間を指揮する存在** として扱う。

| 項目 | 内容 |
|---|---|
| 置き場所 | 試合開始時から終了まで、2人とも **常にリーダーゾーン** にいる。盤面には出ない（登場の概念はない） |
| 攻撃・被害 | リーダーは戦闘に参加せず、攻撃されることも倒されることもない |
| 固有の能力 | 各リーダーが固有の能力（リーダー能力）を持つ。自分の手番に、予備マナ（または通常マナ）を払って使う（1アクション）。**各リーダーにつき1ラウンド1回まで** |
| 成長 | 各リーダーが固有の **成長条件** を持つ。試合中に条件を満たすと「成長」し、リーダー能力が強化される。段階は **通常（Lv1）→ 成長（Lv2）の2段階のみ**。成長は試合終了まで続く |

- 成長条件は、その勢力の戦い方に沿ったものにする。条件を満たそうとすること自体が、デッキとプレイの目標になる。
- 2人のリーダーの組み合わせによる専用のゲーム効果（絆技など）は **設けない**。コンビの個性は、2人の能力と2勢力のカードの噛み合わせで出す。少年同士の関係は、掛け合いのセリフや物語で表現する。

**リーダーの例【仮】**

| リーダー | リーダー能力（通常） | 成長条件 | 成長後の強化 |
|---|---|---|---|
| 見習い騎士の少年（王国騎士団） | 「盾の誓い」（4）: 味方1体に盾を与える | 味方が戦闘ダメージを合計6回耐える | コスト3。パッシブ: 盾を持つ味方すべては+2/+0 |
| 天才ハッカーの少年（電脳都市） | 「強制転送」（5）: ユニット1体を、その持ち主の盤面の空きマスへ動かす | 敵ユニットを合計4回動かす | コスト4。同じプレイヤーの盤面の2マスの中身を入れ替える |
| 落ちこぼれ魔法使いの少年（魔法学院） | 「英知の魔法」（20）: 手札が10枚になるまで引き、通常マナを全回復。パッシブ: スペルを使うたびこの能力のコスト−1 | 英知の魔法を使う | 能力はなくなり、パッシブ: 自分のスペルすべてのコスト−1 |

最新の内容は [cards.md](cards.md) の1章を参照。

## 5. 対戦AI

本作は対AI専用なので、**AIの質がそのままゲームの質になる**。最重要の技術要素として扱う。

### 5.1 方針

- **ズルをしない**: AIもプレイヤーと同じ公開情報だけで判断する（手札や山札の中身を覗かない）。
- **段階的に強くする**: 最初はシンプルなルールベースAIで動くものを作り、あとから探索型AIに置き換える。
- **難易度は「思考の深さ」で調整する**: ステータス補正などのズルで難しくしない。

### 5.2 実装段階

| 段階 | 方式 | 内容 |
|---|---|---|
| 段階1 | ルールベース | 優先度つきの行動ルール（「敵前列が強いレーンには壁役を置く」「空きレーンに攻撃役を置く」など） |
| 段階2 | 評価関数 + 戦闘シミュレーション | 各合法手について「このまま戦闘になったらどうなるか」を計算し、盤面評価が最大の手を選ぶ |
| 段階3 | 探索型 | 情報集合モンテカルロ木探索（ISMCTS）。相手の手札を確率的に推定して、相手の配置まで含めてシミュレーション |

### 5.3 レーン制・同時戦闘とAIの相性

- **良い点**: 戦闘がラウンド終了時に決まった手順で起こるため、「今の盤面で戦闘になったら何が起きるか」を正確に計算できる。段階2の評価が作りやすい。
- **注意点**: 1枚のユニットにつき配置先が最大8マスあり、さらに遊撃・リーダー能力・追加能力もあるので、選べる手の数が多い。探索では「明らかに悪い配置」（例: 射撃を持たない攻撃役を後列に置く）を事前に除外して手の数を絞る。
- **予備マナの判断**: 「今カードを出す」か「マナを残して予備マナに回す」かは、先の展開まで見ないと評価しにくい。評価関数に「予備マナの量」と「使えるリーダー能力」の価値を入れて扱う。

### 5.4 AI用デッキ

- AIデッキは「2人の少年のコンビ」として用意する。試合前に相手のコンビが表示され、会話の掛け合いがある（製品版）。
- 各コンビで、テーマのはっきりした **AIデッキを8〜10個** 用意【仮】。新勢力を追加するたびに、その少年を含むAIデッキも追加する。
- 将来は「プレイヤーのデッキ傾向に合わせてAIデッキを選ぶ」なども検討。

### 5.5 AI実装に必要な設計要件

- ゲームロジックが **UIから完全に分離** されていて、高速にコピー・シミュレーションできること。
- 「現在の状態で可能な合法手の一覧」を返すAPIがあること。
- 「戦闘フェイズだけを単独で計算する」APIがあること（AIの評価と、UIでの戦闘結果プレビューの両方に使う）。
- 乱数のシードを固定でき、同じ試合を再現できること（デバッグ・リプレイ用）。

## 6. UI・UX方針

- **戦闘結果のプレビュー**: 配置・行動フェイズ中、「今このまま戦闘になったら各レーンがどうなるか」（与えるダメージ、倒れるユニット、本体へのダメージ）を盤面上に常に表示する。同時戦闘のルールを直感的に理解できるようにし、読み合いに集中させる。
- 相手（AI）の行動は1手ずつ、何をどこに置いたかが分かるように見せる。
- 勢力ごとにカード枠・色・フォントを変え、世界観の違いが一目で分かるようにする。
- 双方の2人のリーダーをリーダーゾーン（画面の端）に常に表示し、成長条件の進み具合も見せる。リーダー能力の使用時や成長時にはセリフやカットインで盛り上げる（製品版）。
- 通常マナと予備マナは色を分けて表示し、「このコストはどちらで払えるか」がひと目で分かるようにする。

## 8. 技術構成

### 8.1 二段階の開発方針

```
Phase A: ブラウザ試遊版               Phase B: Godot製品版
┌────────────────────────┐             ┌────────────────────────┐
│ UI: TypeScript + DOM/   │             │ UI: Godotシーン         │
│     Canvas (Vite)       │             │                         │
├────────────────────────┤  ロジック   ├────────────────────────┤
│ ゲームエンジン (TS)     │ ─ 移植 ──▶ │ ゲームエンジン (GDScript│
│ AI (TS)                 │             │  または C#)             │
├────────────────────────┤             ├────────────────────────┤
│ カードデータ (JSON)     │ ─ 共通 ──▶ │ カードデータ (JSON)     │
│ テストシナリオ (JSON)   │ ─ 共通 ──▶ │ テストシナリオ (JSON)   │
└────────────────────────┘             └────────────────────────┘
```

### 8.2 試遊版（ブラウザ）

- **言語/ツール**: TypeScript + Vite
- **描画**: まずはDOM + CSS（CSS Gridで4×4の盤面）で最低限のUIを作る（演出は後回し）
- **テスト**: Vitest（ルールエンジン、特に戦闘解決のユニットテストを厚めに）
- **配布**: GitHub Pages などで静的ホスティング
- **保存**: デッキはブラウザのlocalStorageに保存

### 8.3 Godotへの移行を楽にするための設計ルール

1. **ゲームロジックはUI・ブラウザAPIに依存しない純粋なモジュールにする**（状態 + アクション → 新しい状態）。
2. **カード効果はできる限りデータで表現する**（JSONのキーワード/効果定義）。コードで書く特殊効果は最小限にする。
3. **決定的（deterministic）に動くようにする**: 乱数はシード付きの自前RNGを使う。
4. **テストシナリオをJSONで共通化する**: 「初期盤面 + 操作列 → 期待する結果」を両エンジンで実行し、同じ挙動になることを確認できるようにする。戦闘解決は「盤面 → 戦闘後の盤面」のシナリオを多数用意する。
5. Godot側の言語は、TSからの移植しやすさとAI探索の速度を考えると **C#** が有力【仮】。GDScriptにする場合はAI探索の性能を検証する。

## 11. リスクと対策

| リスク | 影響 | 対策 |
|---|---|---|
| 同時戦闘で試合展開が単調になる（毎ラウンド同じ殴り合い） | 面白さの低下 | 移動系のキーワード・スペルや除去で盤面を動かす手段を各勢力に用意する。紙プロトタイプ（M0.5）で早期に確認する |
| 先手・後手の有利不利が偏る | バランス崩壊 | 先手トークンを毎ラウンド交互にし、AI自動対戦で勝率を監視する |
| 後列が安全すぎて、後列に強いユニットを溜め込む展開になる | 膠着 | 前列を倒せば後列を攻撃できるルールで緩和済み。加えて貫通・スペルなど後列に届く手段を各勢力に用意する |
| 移動の手段が少なく、一度の配置ミスが取り返せず窮屈になる | ストレス、逆転の難しさ | 各勢力に少しずつ左右移動の手段（キーワード・スペル）を用意する。戦闘結果プレビューで配置前に結果が分かるようにする |
| 配置先が多く、AIの探索が重い | テンポの悪化 | 明らかに悪い手を除外して手を絞る。思考時間に上限を設け、Web Worker/別スレッドで計算する |
| AIが弱い/不自然でつまらない | ゲームの面白さに直結 | 段階的に強化する。評価関数を調整しやすい作りにする |
| 勢力ごとに世界観が違いすぎて、全体の統一感がなくなる | 見た目の散漫さ | UIの共通部分（盤面・カードのレイアウト）は統一し、違いはカード枠・色・名前に集中させる |
| 勢力が増えるほど、コンビの組み合わせが増えてバランス調整が追いつかない | 強すぎる/弱すぎるコンビの発生 | AI同士の自動対戦で全コンビの勝率を定期的に集計する。コンビ専用のカードは最小限にする |
| 王国騎士団と魔法学院がどちらもファンタジーで、見た目の差が小さい | 「異なる世界」というコンセプトが伝わりにくい | 騎士団は重厚な中世写実寄り、魔法学院は星空と制服の明るい学園もの、と色・フォント・カード名の付け方をはっきり分ける |
| 勢力ごとの制作量（リーダーの絵・セリフ・掛け合い）が膨らむ | 勢力を増やせない | 「勢力パック」の制作物を固定し、掛け合いセリフは汎用パターン＋一部のコンビのみ専用にする |
| リーダー能力が強すぎて、カードを出さずにマナを貯めてリーダー能力を使うだけのゲームになる | 戦略の単調化 | リーダー能力は1ラウンド1回まで。（予備マナの上限は v0.18 でなくした。貯めすぎが強すぎないかを AI 自動対戦で確認する）。AI自動対戦で「カードをほとんど使わない戦い方」が強すぎないか確認する |
| 予備マナと通常マナの使い分けが初心者に分かりにくい | 学習コスト | 2種類のマナを色分け表示し、支払い時は自動で予備マナから優先して使う（手動で変更も可）。チュートリアルで説明する |
| TS→Godotの移植コスト | 二重実装 | データ駆動設計 + 共通テストシナリオで差分を検出する |
| 個人制作のモチベーション維持 | 未完成で止まる | 早い段階で「遊べるもの」を作り、小さく公開してフィードバックをもらう |

## 12. 未決事項（要確認）

### 盤面・戦闘まわり

1. **地形カードの細かいルール**: 自分のマスだけに置けるか、相手のマスにも置けるか。1マスに地形は1つまでか。ユニットが倒れても地形は残るか。

### リーダー・デッキ

2. **1勢力のリーダーは1人か**: 将来、同じ勢力に2人目の少年（ライバル、兄弟など）を追加する可能性はあるか。

### 世界観・コンテンツ

3. **「狭間」の設定** で異世界の少年たちが集まる方向でよいか。
4. **試遊版3勢力のリーダー像** の詳細（名前・性格・少年同士の関係）。
5. **タイトル**
6. **少年たちの年齢層・作風**: 少年漫画風の熱血寄りか、ジュブナイル寄りか。ターゲット層にも関わる。

### その他

7. **試遊版のUIの作り込み**: DOMで最低限か、Canvas/PixiJSなどで演出まで入れるか。
8. **Godot側の言語**: C# か GDScript か。
