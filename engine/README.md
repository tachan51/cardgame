# ルールエンジン（TypeScript、UIなし）

ルール仕様書（[docs/rules.md](../docs/rules.md) v1.9）どおりに試合を進めるライブラリ。
カードは [data/cards](../data/cards) の JSON（[docs/card-data.md](../docs/card-data.md) の形式）を読み込んで動く。
M2 の対戦画面と AI、M4 の AI 同士の自動対戦はこのエンジンを使う。Godot 版に移植するときの基準にもなる。

## 動かし方

```sh
cd engine
npm install
npm test            # 単体テスト・テストシナリオ・ランダムな対戦
npm run typecheck
SIM_GAMES=1000 npm run sim   # ランダムな対戦の数を増やす
npm run stats -- --games 60 --levels normal,normal --out ../docs/stats.md   # AI 同士の自動対戦の集計（4-3）
npm run stats -- --games 4 --levels hard,normal --swap                       # AI の強さの比較
npm run experiment -- --games 20                                               # カードやルールを仮に変えて比べる（4-4）
npm run mulligan-table                                                         # AI のマリガンの表（src/mulligan-table.json）を作り直す
npx tsx scripts/mulligan-ab.ts --games 100 --policies smart,cost               # マリガンの方針どうしを比べる
```

## 使い方

```ts
import { buildCatalog, newGame, applyAction, legalActions, publicView } from './src';

const cat = buildCatalog([knights, cyber, academy]); // data/cards/*.json（不正なデータなら CatalogError）
let s = newGame(cat, { A: deckA, B: deckB }, { seed: 42 }); // 双方4枚引いてマリガン待ち
s = applyAction(cat, s, { type: 'mulligan', player: 'A', cards: [] });
s = applyAction(cat, s, { type: 'mulligan', player: 'B', cards: [] });
while (!s.result) {
  const acts = legalActions(cat, s); // 今行える手の一覧
  s = applyAction(cat, s, choose(publicView(s, s.activePlayer), acts));
}
```

- **状態 + アクション → 新しい状態**: `applyAction` は元の状態を変えずに新しい状態を返す。行えないアクションなら `IllegalAction` を投げる。
- **自動で進む部分**: 手番の始めの遅延効果の発動、双方のパス後の戦闘・終了フェイズ・次のラウンドの開始は `applyAction` の中で進む。返ってきた状態は、必ず誰かの判断を待っている（または試合が終わっている）。
- **効果の途中の選択**: 「山札の上から見て1枚選ぶ」のような選択は `state.pending` に選択肢が入る。`{ type: 'choose', option }` で答える。
- **公開情報**: AI には `publicView(state, player)` を渡す。相手の手札（公開されたものを除く）と山札の中身が隠れる。
- **戦闘のプレビュー**: `previewCombat(cat, state)` は「このまま戦闘になったら」の結果を返す（元の状態は変えない）。予約中の遅延効果は戦闘の前に必ず発動するので、先に発動させてから計算する。
- **AI**: `chooseAction(cat, state, player, { level })` が手を返す。詳しい仕様は [docs/ai.md](../docs/ai.md)。相手の手札と山札の中身は見ない。強さは3段階。
  - `easy`（段階1）: 合法手を1つずつ試し、このラウンドの戦闘の結果まで見た評価で選ぶ。評価に揺らぎを入れて手加減する。
  - `normal`（段階2）: 評価に、手札のカードの重さ・予備マナ・次のラウンドに使えるリーダー能力の価値を加える（AI 同士の対戦で重みを調整）。
  - `hard`（段階3）: 段階2で良さそうな手を6つに絞り、相手の手札と山札を相手の勢力のカードから推測した「ありうる状況」を3通り作る。それぞれでラウンドの終わりまで双方が段階2の方針で打ち進め（ロールアウト）、平均の評価で選ぶ。思考時間に上限がある。
  - 強さの目安（AI 同士、先手とデッキを入れ替えて）: normal は easy に約56%、hard は normal に約63% 勝つ。1手の思考時間は normal 約8ms、hard 約170ms。
- **決定性**: 乱数は状態の中（`rngState`）にある。同じシードと同じアクション列なら必ず同じ結果になる。
- **ログ**: `state.log` に、すべてのアクションと出来事（ダメージ・破壊・移動・成長など）が順番に入る。

## 構成

| ファイル | 内容 |
|---|---|
| `src/types.ts` | カードデータ・状態・アクションの型 |
| `src/catalog.ts` | カードデータの読み込みと検証、デッキの条件（3.1） |
| `src/engine.ts` | 対戦開始、マリガン、各アクションの実行、手番の進め方 |
| `src/runner.ts` | 効果の処理、誘発、戦闘、ラウンドの進行、勝敗、リーダーの成長 |
| `src/legal.ts` | 合法手の一覧 |
| `src/view.ts` | 公開情報、戦闘のプレビュー（予約中の遅延効果を先に発動させる） |
| `src/ai.ts` | AI（段階1〜3）。`chooseAction(cat, state, player, { level })` |
| `src/sim.ts` | AI 同士の自動対戦（`playGame`）と集計（`summarize`・`toMarkdown`） |
| `scripts/stats.ts` | 自動対戦をまとめて行い、集計を Markdown で出す（CPU の数だけ並列に動かす） |
| `scripts/mulligan-table.ts` | AI のマリガンに使う表（相手の勢力ごとの、初手にあると勝ちやすいカード）を自動対戦から作る |
| `scripts/mulligan-ab.ts` | マリガンの方針どうしを、同じシードで入れ替えて比べる |
| `scripts/experiment.ts` | カードやルールを仮に変えた「実験」ごとに自動対戦し、デッキの勝率・試合の長さ・リーダーの成長を比べる |
| `src/scenario.ts` | テストシナリオの実行（[scenarios/README.md](scenarios/README.md)） |
| `scenarios/*.json` | テストシナリオ（ルールの例、カードごとの動き） |
| `test/` | 単体テスト、シナリオの実行、ランダムな対戦 |

## 実装で決めた細部

ルール仕様書に書かれていない点は、次のように実装した。遊んでみて変える場合は、ルール仕様書に反映してからエンジンを直す。

| # | 項目 | 実装 |
|---|---|---|
| 1 | 貫通で後列のユニットに流れたダメージが、さらにその残り体力を超えた場合 | 超えた分は相手本体に与える（「相手の後列 → 相手本体」の順に流れる） |
| 2 | 終了フェイズの手順1の順番 | 「ラウンド終了時」の誘発効果（11.3 の順）→ 効果で予約した「このラウンドの終了時」の処理（CY-07・AC-14。予約した順） |
| 3 | 手札にある間の効果（`inHand`）の処理順 | 同じプレイヤーの効果の中で、盤面 → リーダー → 手札の順 |
| 4 | 常時効果の条件（「盾を持つ味方」など） | 常時効果を含まない値で判定する（常時効果どうしが循環しないように） |
| 5 | 回復 | 永続の体力が受けたダメージから先に減らす |
| 6 | 対象を2つ選ぶ効果（AC-15・AC-25）で候補が1つしかない場合 | あるだけ選ぶ。スペルは1つも選べなければ使えない |
| 7 | 配置時の効果の対象がいない場合 | 配置はでき、その効果は何もしない（7.1・11.4） |
| 8 | 起動能力・リーダー能力の対象がいない場合 | 使えない（7「対象がいない」） |
| 9 | 山札の上から見て選んだカードを加えるとき手札が上限 | トラッシュに置く |
| 10 | 同時に起きた誘発効果 | 1つの出来事（破壊・移動など）ごとに 11.3 の順に並べ、順番待ちの列の最後に加える |
| 11 | 「戦闘ダメージを耐える」 | 戦闘のステップごと・ユニットごとに1回。騎士の決闘（KN-07）の `fight` は戦闘ではないので数えない |
| 12 | ユニットを移動させた回数（レイ） | 自分が使ったカード・能力の効果、または自分の遊撃で、ユニット（敵味方問わず）が1体移動するごとに1回（入れ替えで2体動けば2回）。相手の遊撃による移動は数えない |
| 13 | 盾を持つユニットが、同じステップで複数の攻撃を受けた場合 | 前列のユニットの攻撃 → 後列のユニットの攻撃の順に当たるものとし、最初の1回を防ぐ（8.4 の割り当ての順と同じ） |
| 14 | 「味方ユニットすべて」の配置時の効果（KN-21・KN-24） | 配置したユニット自身も含む（7.1 で配置してから配置時の効果を処理するため） |
| 15 | 「体力X以下」（AC-24） | 残り体力で判定する |
| 16 | 禁書の閲覧（AC-18）で、使ったスペルの名前が1種類しかない場合 | 1枚だけ生成する |
| 17 | 成長したノエル | リーダー能力は使えない（コスト0になるのではない） |
| 18 | 起動能力の「このユニットがいるレーン」（KN-17・CY-18） | 起動したとき（予約したとき）のレーンに決まる（card-data.md 6.5） |
| 19 | 衛星兵器「ラグナロク」（CY-25）の強化の盾 | 使ったときに盤面にいる味方だけに与える |
| 20 | 首席の少女（AC-16） | 自分のスペルの強化コストだけが下がる（ユニットの強化コストは下がらない） |
| 21 | ライフの回復（AC-05・AC-23・ノエル） | 上限はない（初期ライフを超えて回復できる） |
| 22 | 「名前の異なるスペル3枚」を山札から加える（AC-25） | 山札にある名前の種類が3つより少なければ、あるだけ加える |
